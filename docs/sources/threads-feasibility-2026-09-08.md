# Threads 공식 API 재검토

확인일: 2026-09-08. 공식 문서를 브라우저로 직접 읽은 기술·정책 검토이며 법률 자문이나 Meta 승인 결과가 아니다. 실제 서비스명, 검색어, 게시물, 계정, 운영 통계는 기록하지 않는다. API 실호출 및 앱 대시보드 확인은 수행하지 않았다.

## 결론

공개 피드백 검색용으로 조건부 도입 후보다. 검색 API와 허용 용도 근거가 있으나, 타인 공개 글 검색에는 검색 권한 승인이 필요하다. 승인 이전의 개발 테스트와 승인 이후의 실서비스 수집을 구분해야 한다. 수집량이나 심사 통과 가능성은 아직 검증되지 않았다.

## 공식 문서로 확인한 내용

- [키워드 검색](https://developers.facebook.com/documentation/threads/keyword-search): `threads_basic`, `threads_keyword_search` 필요. 검색 권한 미승인 시 인증 사용자 소유 게시물만 검색되고, 승인 후 공개 게시물을 검색한다. 일반적인 앱 역할 사용자 테스트 예외를 이 제한의 우회 근거로 삼으면 안 된다.
- 같은 문서: 최신순 `RECENT`, 키워드·태그 검색, `since`/`until` 기간 지정 지원. 한 요청의 기본 반환 상한 25, 최대 100. 이를 전체 검색 가능량 100건으로 단정하지 않는다. 페이지네이션 및 검색 완전성은 실측 필요.
- 같은 문서: 사용자당 롤링 24시간 2,200쿼리이며 같은 사용자의 여러 앱이 한도를 공유한다. 결과 없는 쿼리는 차감되지 않는다. 민감하거나 불쾌하다고 판단한 검색어에는 빈 배열을 반환한다. 특정 검색어의 차단 여부를 이번에 확인한 것은 아니다.
- [권한 레퍼런스](https://developers.facebook.com/docs/permissions/reference/)의 `threads_keyword_search`: 사용자 대신 키워드로 콘텐츠를 검색·조회하여 소셜 미디어 활동을 관리하는 용도. 재식별 불가능한 집계·비식별/익명 정보를 통한 앱 개선 및 마케팅·광고 분석도 설명한다. 이 설명을 임의의 원문 분석·무기한 축적에 대한 포괄적 허가로 해석하면 안 된다.
- 같은 권한 레퍼런스: 심사에 용도 설명과 OAuth 로그인, 계정 연결·권한 부여, 키워드 입력·공개 콘텐츠 검색의 화면 녹화를 요구한다. 현재 목록의 게시물 생성 결과 시연 문구가 읽기 전용 앱에 어떻게 적용되는지는 심사에서 확인할 사항이다. 불필요한 게시 권한을 추가할 근거는 아니다.
- [시작하기](https://developers.facebook.com/documentation/threads/get-started): 단기 토큰 1시간, 장기 토큰 60일. 만료 전 갱신 필요. 권한 유효기간과 토큰 유효기간은 구분한다.
- [앱 검수](https://developers.facebook.com/documentation/resp-plat-initiatives/individual-processes/app-review): 검수자가 앱 및 요청 권한의 기능을 테스트할 수 있어야 한다.
- [비즈니스 인증](https://developers.facebook.com/docs/apps/business-verification): 고급 액세스를 요청하는 앱 등의 인증 비즈니스 연결 요건과 역할 사용자만 쓰는 앱의 일반적 예외가 함께 설명돼 있다. 공개 검색 권한 승인과 비즈니스 인증을 동일시하지 않는다. 해당 앱의 고급 액세스·인증 요구는 대시보드에서 최종 확인해야 한다. '법인만 가능'은 이번 근거로 단정할 수 없다.

## 저장 및 외부 AI 처리

[Meta 플랫폼 약관](https://developers.facebook.com/terms/dfc_platform_terms/)은 페이지상 2026-02-03 개정본을 확인했다.

- 제3.a: 허용 목적 외 처리, 감시, 유효한 동의 없는 사용자 프로필 구축 등을 금지한다. 서비스 문제 유형을 파악하는 것과 작성자별 성향·취향 프로필을 구축하는 것은 구분해야 한다.
- 제3.d: 요청 시 신속한 수정·삭제, 삭제 요청 수단, 적법한 사업 목적상 더 이상 필요하지 않은 데이터의 삭제 등을 요구한다. 이번 확인 범위에서 Threads 전체에 적용되는 고정 30일 보관 상한을 확인한 것은 아니다. 무기한 보관이 허용된다는 뜻도 아니다.
- 제4조: 공개 접근 가능한 개인정보처리방침에 데이터, 목적, 처리 방법, 삭제 요청 방법을 명시해야 한다.
- 제3.c 및 제5.a: 요청한 서비스 제공을 위한 서비스 제공업체 공유 경로는 있다. 제공업체가 자체 목적이 아닌 요청된 업무만 처리하고 관련 의무를 준수하도록 서면 약정 등이 필요하다. 외부 LLM 추론도 이 조건 및 실제 제공업체 계약을 검토해야 한다. 학습 미사용 설정만으로 모든 요건이 충족되는 것은 아니다.
- 제12.l: 익명·집계·파생 데이터도 플랫폼 데이터에 포함한다. 요약 후 원문을 지웠다고 약관에서 자동으로 벗어나지 않는다.
- 제11.f: 플랫폼이 항상 무료라는 보장은 없다. 확인한 문서에 별도 호출 단가·유료 플랜은 제시되지 않았지만, 이를 영구 무료 보장으로 기록하지 않는다.
- [제3.e 예외](https://developers.facebook.com/terms/3e/)에 일반적인 Threads 공개 검색 데이터는 열거돼 있지 않았다.
- [개발자 정책](https://developers.facebook.com/devpolicy/): 앱 콘텐츠의 커뮤니티 규정 준수 및 해당하는 연령·콘텐츠 접근 제한도 검토해야 한다.

## 권고 도입 순서

1. 읽기 전용 검색·원문 링크 표시 기능과 OAuth 연결, 개인정보처리방침, 삭제 요청 수단을 준비한다.
2. 승인 전에는 자체 테스트 게시물로 동작을 검증한다. 실제 운영 데이터를 심사 예시로 무단 제출하지 않는다.
3. 대시보드에서 검색 권한의 고급 액세스 및 인증 요구를 확인하고, 실제 수집·분석·보관·외부 처리 목적을 그대로 설명해 심사를 요청한다. 조직 명의 사용은 대표 권한을 확인해야 한다.
4. 승인 후 허가된 범위에서 짧은 기간 파일럿을 운영하여 관련 글 수, 중복, 원문 대비 검색 누락, 빈 결과를 확인한다. 빈 배열만으로 '불만 없음'을 표시하지 않는다.
5. 외부 AI 전달은 계약·삭제·재위탁·국외 처리 조건 검토 후 연결한다. 원문 보관 기간은 목적에 필요한 범위로 정하고 수정·삭제를 반영한다.

## 기존 조사에서 수정이 필요한 해석

- '승인 전 본인 글만 검색'은 이번에 공식 문서로 재확인됐다.
- '공식 API 승인 후 적법'은 너무 강하다. 승인 후에도 약관·개인정보·저작권 의무가 남는다.
- '법인 인증 3단계가 모든 경우 필수'는 일반 예외와 앱별 요구를 구분하도록 보완해야 한다.
- '100건이 전체 검색의 천장'은 한 요청의 반환 상한과 구분해야 한다.
- '0원 확정' 대신 현재 확인한 문서에 별도 과금표가 없으며 미래 무료 보장은 없다고 기록한다.

기존 문서는 과거 조사 기록으로 유지했다. 이 메모 작성만으로 수집기를 활성화하거나 심사를 신청하지 않았다.
