# 수집 채널 적법성 근거

이 도구가 외부에서 글을 가져오는 **모든 경로에 대해, 그 경로를 써도 되는 근거가 무엇인지**를 정리한 문서다.
"일단 브라우저로 열어서 긁는다"가 아니라 **경로마다 문서화된 근거를 붙이는 것**이 목적이다.

> **이 문서는 법률 자문이 아니다.** 기술 담당자가 직접 실측한 사실(HTTP 응답, robots.txt 원문, 공식 문서)과
> 공개된 판례를 정리한 것이다. 최종 판단은 법무 검토가 필요하다. 아래에서 **판정**이라고 적은 것은
> 법적 결론이 아니라 "이 근거들로 볼 때 어느 쪽인지"에 대한 실무 의견이다.

- **실측일: 2026-08-29** (robots.txt는 예고 없이 바뀐다. [재확인 방법](#8-재확인-방법)을 6개월마다 돌린다)
- 실측 대상 코드: [apps/pipeline/src/collectors/](../apps/pipeline/src/collectors/)
- **짝 문서**: [공식 API 전환 계획](official-api-migration.md) — 이 문서가 "적법한가"를 판정하고,
  그쪽이 "그래서 어떻게 옮기나, 얼마나 옮길 수 있나"를 다룬다

## 2. 무엇을 기준으로 판단했나

크롤링 적법성은 단일 조항으로 정해지지 않는다. 아래 4개 층위를 각각 본다.
**층위가 다르면 결론도 다를 수 있다** (뒤의 판례 참고: 형사는 무죄인데 민사는 10억 배상).

| # | 층위 | 근거 | 위반 시 |
|---|---|---|---|
| 1 | **robots.txt** | [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html) | 그 자체로 위법은 아니다. 다만 사이트의 **명시적 거부 의사**가 문서로 남은 것이라, 분쟁 시 "몰랐다"가 통하지 않는다 |
| 2 | **이용약관 / 개발자 약관** | 각 서비스 약관 | 계약 위반. 계정 정지, 서비스 차단 |
| 3 | **기술적 보호조치 우회** | 정보통신망법 제48조 | 로그인 벽·IP 차단을 우회하면 형사 리스크. 우회하지 않으면 리스크가 크게 낮아진다 |
| 4 | **수집 후의 이용 형태** | 저작권법(제93조 데이터베이스제작자의 권리), 부정경쟁방지법, 개인정보보호법 | 민사 손해배상. **여기가 실제로 돈이 오간 지점이다** |

### 국내 판례가 그은 선

| 사건 | 결론 | 이 프로젝트에 주는 시사점 |
|---|---|---|
| **대법원 2022. 5. 12. 선고 2021도1533** (야놀자 v 여기어때, 형사) | **무죄 확정.** "일반 이용자들은 회원 가입 없이도 자유롭게 서버에 접근할 수 있었고, 접근을 막는 별도 보호조치가 없었다"는 이유로 정보통신망 침입을 부정 ([법률신문](https://www.lawtimes.co.kr/news/178683?serial=178683), [ZDNet](https://zdnet.co.kr/view/?no=20220512180515)) | **비로그인으로 열리는 공개 페이지를 사람 속도로 읽는 것**은 형사 리스크가 낮다. 우리 원칙이 여기에 맞춰져 있다 |
| **서울중앙지법 민사합의63-2부 (2021. 8.)** — 같은 사건 민사 | **10억원 배상.** 데이터베이스 구축에 든 노력·투자를 인정해 부정경쟁행위로 판단 ([한국경제](https://www.hankyung.com/article/202108230529Y), [한국일보](https://www.hankookilbo.com/news/article/A2021082313250001154)) | **형사 무죄여도 민사는 별개다.** robots.txt를 지켜도 "원문 DB를 통째로 복제해 남의 서비스를 대체"하면 걸린다 |
| **잡코리아 v 사람인** | 1심 1.98억 → 2심 4.5억(DB권 침해 + 간접강제금), 2018년 120억 합의. **IP 차단을 VPN으로 우회한 점**이 불리하게 작용 ([법률신문](https://www.lawtimes.co.kr/news/98844?serial=98844), [법무법인 민후](https://www.minwho.kr/kr/business/business_case_view.php?bgu=view&idx=32903)) | **차단당했는데 뚫는 순간 성격이 바뀐다.** 403이 오면 멈춰야 한다 |

### ⚠️ "과징금"과 "손해배상"은 다른 경로다

크롤링 사고를 뭉뚱그려 "과징금 맞는다"고 말하기 쉬운데, **돈이 나가는 경로가 둘이고 성격이 다르다.**
대비하는 방법도 다르므로 갈라 둔다.

| | 손해배상 (민사) | 과징금 (행정) |
|---|---|---|
| **누가** | 긁힌 **사이트 주인**이 소송을 건다 | **개인정보보호위원회** 같은 규제기관이 부과한다 |
| **왜** | 저작권법(데이터베이스제작자의 권리), 부정경쟁방지법 | 개인정보보호법 위반 |
| **위 판례** | 잡코리아·야놀자 사건이 **전부 이쪽이다** | 해당 없음 |
| **금액** | 잡코리아 v 사람인 2심 4.5억, 2018년 합의 120억 / 야놀자 민사 10억 | 매출액 기준 정률 부과가 가능해 규모가 다르다 |
| **막는 법** | 원문 DB를 복제·대체하지 않는다. 사이트의 거부 의사를 존중한다 | 개인정보를 최소로 수집하고, 보유기간을 정하고, 지난 것은 지운다 |

**이 도구는 둘 다 해당된다.** 본문 발췌를 저장하므로 앞쪽이 걸리고,
**작성자 닉네임을 저장하므로 뒤쪽도 걸린다**(→ [6절](#6-개인정보-측면)).
지금까지 이 문서가 다룬 robots.txt·약관은 앞쪽 리스크를 낮추는 장치이지,
**뒤쪽(개인정보)은 robots.txt를 아무리 잘 지켜도 별개로 남는다.**

### 이 프로젝트가 민사 리스크에서 다른 점

위 판례들은 전부 **경쟁사가 상대 DB를 복제해 자기 서비스에 재게시한** 사안이다. 이 도구는 성격이 다르고,
그 차이가 방어 논거가 된다. 다만 **차이를 유지하는 것이 조건**이라 코드에 못 박아 둬야 한다.

| 판례 사안 | 이 도구 |
|---|---|
| 수집한 원문을 자기 서비스에 **재게시**(대외 공개) | **외부 미공개.** 외부에 공개하지 않는다 |
| 원문 DB를 **대체**해 이용자를 뺏음 | 원문을 대체하지 않는다. **모든 인용에 원문 링크를 병기**해 원문으로 보낸다 |
| 대상 사이트 데이터 **전체**를 긁음 | **자사 서비스 언급 글만** 키워드로 걸러 가져온다 |
| 상업적 재판매 | 자사 서비스 개선을 위한 **VOC 모니터링** |

> ⚠️ **다만 본문 발췌를 저장하고 있다는 사실은 남는다** (디시 800자, 더쿠·다음 카페는 본문 전문).
> 분류 정확도를 위한 것이지만, "인용의 정당한 범위"([저작권법 제35조의5](https://www.law.go.kr/법령/저작권법) 공정이용)에 관한 판단은
> 법무 검토가 필요한 부분이다. → [7-4 저장 범위 최소화](#7-4-저장-범위를-최소화한다) 참고

- **인증**: `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`

**근거**: 크롤링이 아니라 **네이버가 발급한 키로 호출하는 공식 검색 API**다.
키 발급 과정에서 이용약관에 동의하며, 호출 쿼터도 네이버가 정한다. robots.txt는 애초에 적용 대상이 아니다.

- 문서: <https://developers.naver.com/docs/serviceapi/search/blog/blog.md>
- 발급: NAVER Cloud Platform → NAVER API HUB

> ⚠️ 쇼핑·책·전문자료 검색은 2026-07-31 종료됐다. 블로그·카페글 검색만 HUB로 이관돼 살아 있다.

### 🟠 약관에 저장·캐싱 조항이 있다 (2026-08-29 확인)

**앞서 "확인하지 못했다"고 남겼던 항목의 답이 나왔다. 조항은 있다.**
robots.txt 층위(층위 1)는 애초에 적용 대상이 아니라 문제가 없지만, **약관 층위(층위 2)가 걸린다.**

✅ [네이버 개발자센터 이용약관](https://developers.naver.com/products/terms/) **7.3 ③ — 원문:**

> ③ API서비스를 이용하여 취득한 정보(네이버 회원의 계정 관련 정보, 네이버 서비스의 컨텐츠 내용 등
> 일체의 데이터를 포함한다)를 다음의 예시와 같이 본 약관에서 허용한 범위를 넘어서서 무단으로
> 복제, **저장(캐시 행위 포함)**, 가공, 배포 등 이용하거나 제3자에게 제공하는 행위

**카카오보다 더 명시적이다.** 카카오는 "캐시"라고만 했는데 네이버는 **"저장(캐시 행위 포함)"**으로
저장 자체를 앞세웠다.

#### 다만 절대 금지가 아니다 — "다음의 예시와 같이"가 핵심이다

조항이 든 예시를 그대로 옮기면 이렇다.

> - 네이버 회원의 정보를 피싱이나 스팸/광고 전송 등을 위해 이용하는 행위
> - 네이버 지역정보를 수집하여 해당 정보를 광고 영업에 이용하는 행위
> - 네이버 지역정보를 수집하여 **별도 데이터베이스로 관리하며 이용하는 행위**
> - 기타 각 API의 **제공 취지나 목적에 맞지 않게** API 제공 정보를 저장하거나 이용하는 행위

**판단 기준은 "저장했느냐"가 아니라 "API의 제공 취지에 맞느냐"다.** 그래서 우리 설계에서
실제로 닿는 지점은 둘이다.

| 우리 설계 | 닿는 조항 | 성립 여부 |
|---|---|---|
| 검색 결과를 `items` 표에 **영구 적재하고 갱신하지 않음** | 세 번째 예시 "별도 데이터베이스로 관리하며 이용" | 🟠 그 예시는 **지역정보** 한정이다. 검색 결과에 그대로 미치는지는 해석이 갈린다 |
| 본문을 분류하려고 **LLM 제공자에게 전달** | 같은 조 "**제3자에게 제공**", 그리고 ⑥ "API서비스를 다시 제3자에게 제공하는 행위" | 🟠 분류 목적의 일시 전달이 "제공"인지 판단 필요 |

**그래서 판정을 🟢에서 🟡로 내린다.** robots.txt·우회 문제는 없고 키를 정식 발급받아 쓰지만,
**약관에 실재하는 저장 조항의 허용 범위 안인지가 미확정**이기 때문이다.
카카오처럼 "정면으로 걸린다"고까지는 못 하는데, 네이버 조항에는 **최신성 유지 의무 문구가 없어서**다.

> ⚠️ **이 조항은 지금 돌고 있는 경로에 걸린다.** 앱스토어·구글플레이처럼 "전환하면 해결"되는 문제가
> 아니라, **이미 그 API를 쓰고 있는 상태에서 발생하는 문제**다. 법무 검토 우선순위가 가장 높다.
> 자세한 것은 [소스별 문서](sources/naver.md).

### 4-2. X — `api` 경로는 적법, `web` 경로는 위반

- **코드**: [x.ts](../apps/pipeline/src/collectors/x.ts) (api) / [x-web.ts](../apps/pipeline/src/collectors/x-web.ts) (web)

#### `api` — 적법

`GET https://api.x.com/2/tweets/search/recent`. X Developer Portal에서 발급한 Bearer 토큰으로 호출하는
공식 API다. 읽기 1건당 $0.005 종량제. 약관 안에서 돌아가고, 계정 정지 리스크가 없다.

#### `web` — 위반

`x.com/search?q=...&f=live`를 Playwright로 열고, 저장해 둔 `auth_token` 쿠키로 로그인 상태를 만든다.

**robots.txt 실측 (`https://x.com/robots.txt`, HTTP 200):**

```
# Every bot that might possibly read and respect this file
# ========================================================
User-agent: *
Disallow: /
```

Googlebot 그룹에도 검색 실시간 탭이 따로 차단돼 있다:

```
Disallow: /search/realtime
```

**두 가지가 겹친다.**

1. robots.txt가 **전체 경로를 차단**한다. 우리는 명명된 크롤러가 아니므로 `User-agent: *` 규칙이 적용된다.
2. **X는 비로그인 검색을 막아 뒀고, 우리는 로그인 쿠키로 그 벽을 넘는다.**
   [2절 층위 3](#2-무엇을-기준으로-판단했나)에 해당한다. 잡코리아 사건에서 VPN 우회가 불리하게 작용한 것과 성격이 같다.

README도 이미 이것을 "원칙의 의도된 예외"이자 약관 위반으로 명시하고 있다. **회사 이름으로 운영한다면
이 경로는 켜면 안 된다.**

**→ 대체: `api` 경로로 고정.** 코드에 이미 있다. 설정에서 `X 경로`를 `api`로 바꾸면 끝난다.
비용은 월 예산 상한($50 기본)으로 통제된다.

### 4-3. Threads — 위반

- **코드**: [threads.ts](../apps/pipeline/src/collectors/threads.ts)
- **경로**: `https://www.threads.com/search?q={키워드}&serp_type=default` (Playwright, 비로그인)

**robots.txt 실측 (`https://www.threads.com/robots.txt`, HTTP 200):**

파일 **맨 앞에** 고지문이 있다.

```
# Notice: Collection of data on Threads through automated means is
# prohibited unless you have express written permission from Threads
# and may only be conducted for the limited purpose contained in said
# permission.
# All authorized user-agents listed on this page must comply with Meta’s
# Automated Data Collection Terms available at:
# https://www.facebook.com/legal/automated_data_collection_terms
```

그리고 파일 끝(352번째 줄):

```
User-agent: *
Disallow: /
```

**robots.txt 중에서도 가장 명확한 형태의 금지다.** "서면 허가 없는 자동 수집 금지"를 자연어로 못 박고,
허용 목록에 없는 모든 에이전트를 전면 차단한다. 비로그인이라도 다르지 않다.

- Meta 자동 데이터 수집 약관: <https://www.facebook.com/legal/automated_data_collection_terms>

**→ 대체 경로: 있다. 공식 Threads API에 키워드 검색이 있다.**

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `GET https://graph.threads.net/v1.0/keyword_search` |
| 필요 권한 | `threads_basic` + **`threads_keyword_search`** |
| 한도 | 롤링 24시간 기준 **2,200 쿼리** (결과가 0건인 쿼리는 차감되지 않음) |
| ⚠️ 제약 | **권한 승인 전에는 인증한 계정 본인의 글만 검색된다.** 승인을 받아야 공개 글이 검색된다 |
| 문서 | <https://developers.facebook.com/docs/threads/keyword-search/> |

robots.txt가 말한 "서면 허가"의 실체가 이것이다. **Meta 앱 심사에서 `threads_keyword_search` 권한을
승인받으면 적법한 경로가 열린다.** 승인 전까지는 이 소스를 켜면 안 된다.

> 🔴 **지금 켜져 있다.** 예시 설정(`feedback-radar.config.example.json`)과 프리셋에서는 꺼져 있지만,
> **운영 설정(`settings` 표의 `config`)에는 `"threads": true`로 들어 있다** (2026-08-29 DB 실측).
> 즉 다음 수집 실행에서 이 경로가 돈다. **코드 작업과 무관하게 오늘 끌 수 있고, 꺼야 한다.**
> 승인까지의 절차는 [공식 API 전환 계획 2-2](official-api-migration.md#2-2-threads--심사가-병목-코드는-그-다음) 참고.

### 4-4. 디시인사이드 — 층위가 충돌한다

- **코드**: [dcinside.ts](../apps/pipeline/src/collectors/dcinside.ts)
- **경로**: `https://search.dcinside.com/post/q/{키워드}/p/{쪽}` (Playwright, 비로그인)
- **저장**: 검색 결과 목록의 제목 + 발췌(최대 800자) + 원문 링크. **본 갤러리 페이지는 요청하지 않는다.**

#### 🔴 이용약관이 크롤링을 명시적으로 금지한다 (2026-08-30 확인)

**앞서 이 문서는 "확인된 약관 페이지 없음"이라고 적었다. 그것이 틀렸다.**
약관은 있고, 경로를 추측해서는 못 찾는다 — 푸터 링크로만 도달한다.

✅ [디시인사이드 이용약관](https://nstatic.dcinside.com/dc/w/policy/policy_index.html) (시행일 2026-07-21) — 원문:

> **제16조 (크롤링 및 인공지능 학습)**
> ① 회사는 robots.txt에 적용한 일부 사이트에만 크롤링을 허용하고 있습니다. 당사의 사전 서면 동의 없이
> 어떤 형태로든 어떤 목적으로든 본 서비스를 크롤링하는 행위는 명시적으로 금지됩니다.
> ② 회사의 콘텐츠를 인공지능 학습용 데이터(…) 등에 활용할 때 반드시 회사와 사전 합의해야 합니다.
> 공익 및 비영리 목적인 경우에도 회사의 동의를 받아야 합니다. 그렇지 않을 경우, 민형사상 책임을 물을 수 있습니다.

> **제11조 (이용자의 의무) ① 13)**
> 자동화된 수단을 이용하여 서비스에 게재된 콘텐츠를 비롯한 기타 정보(고정닉, 닉네임, 비회원의 일부 IP 등)를
> 수집하거나 인공지능(AI) 학습을 목적으로 수집, 이용하는 행위

> **제14조 (저작권의 귀속 및 콘텐츠의 이용) ②**
> 이용자는 회사가 제공하는 서비스를 이용함으로써 얻은 정보를 회사의 사전 승낙 없이 복제, 전송, 출판, 배포,
> 방송, 기타 방법에 따라 영리목적으로 이용하거나 제3자에게 이용하게 하여서는 안 됩니다.

**층위 1(robots.txt)과 층위 2(약관)가 정반대를 가리킨다.**

| 층위 | 결과 |
|---|---|
| 1. robots.txt | 🟢 허용 (`gall`·`www`가 `User-agent: *` → `Allow: /`, 요청 호스트는 robots.txt 없음) |
| 2. 이용약관 | 🔴 **명시적 금지** (제16조 ①) |
| 3. 보호조치 우회 | 🟢 해당 없음 (비로그인, 우회 없음) |
| 4. 이용 형태 | 🟡 제14조 ②의 "영리목적"에 VOC 모니터링이 해당하는지 미확정 |

#### 두 층위를 어떻게 읽을 것인가

제16조 ①의 **첫 문장이 열쇠다** — "robots.txt에 적용한 일부 사이트에만 크롤링을 허용하고 있습니다."
디시 스스로 **robots.txt를 허가의 통로**로 설명한다. 그렇게 읽으면 `Allow: /`인 호스트는 허가에 해당한다.

**그런데 우리가 실제로 때리는 호스트는 `search.dcinside.com`이고, 거기에는 robots.txt가 없다.**

| 읽는 방식 | 결론 |
|---|---|
| RFC 9309 (robots.txt 없음 = 제한 없음) | 허용 |
| 제16조 ① (robots.txt가 허가의 통로 = 없으면 허가 없음) | **금지** |

**후자가 조항의 문언에 더 가깝다.** 그리고 제11조 ① 13)은 robots.txt와 무관하게
자동화 수집 자체를 이용자 의무 위반으로 규정한다.

> ⚠️ **이것이 [10절 결정](#10-결정-기록-2026-08-29)의 전제를 뒤집는다.**
> 그 결정은 "디시는 명시적 허용이라 남기고, 더쿠는 회색지대라 접는다"였다.
> 약관을 확인한 지금 보면 **금지 문서가 있는 쪽은 디시이고, 더쿠에는 금지 문서가 없다.**

**robots.txt 실측:**

| 호스트 | 상태 | 내용 |
|---|---|---|
| `search.dcinside.com` | **HTTP 404** — robots.txt 없음 | 이 호스트에 대해 **명시된 제한이 없다** |
| `gall.dcinside.com` | HTTP 200 | `User-agent: *` → `Allow: /` (일부 갤러리·게시물만 개별 Disallow) |
| `www.dcinside.com` | HTTP 200 | `User-agent: *` → `Allow: /` |

**우리가 실제로 요청하는 호스트에는 robots.txt가 없고, 본 갤러리는 일반 봇에게 열려 있다.**
RFC 9309상 robots.txt가 없으면 제한이 없는 것으로 본다. 로그인 벽도 없다.

#### 다만 세 가지를 짚어야 한다

**(1) 디시는 AI 학습 크롤러를 명시적으로 차단한다.** `gall.dcinside.com/robots.txt` 맨 앞:

```
# ----- AI 학습 크롤러 차단 -----
User-agent: GPTBot
Disallow: /
User-agent: ClaudeBot
Disallow: /
User-agent: anthropic-ai
Disallow: /
...
User-agent: Google-Extended
Disallow: /
```

이 도구는 수집한 글을 LLM에 넣어 **분류**한다(학습이 아니라 추론). 학습 크롤러 차단과 성격이 다르다는 것이
우리 입장이지만, **디시가 AI 관련 자동 수집에 부정적이라는 의사를 문서로 표시했다는 사실은 남는다.**
법무 검토 시 짚어야 할 항목이다.

**(2) 갤러리 단위 Disallow가 있다.** `gall.dcinside.com/robots.txt`는 특정 갤러리를 차단한다
(`id=47`, `cat`, `dog`, `stock_new`, `baseball_new8`, `m_entertainer1`, `produce48`, `singo` 등).
우리는 통합검색 결과를 읽으므로 **차단된 갤러리의 글이 결과에 섞여 들어올 수 있다.**
→ [7-2](#7-2-robotstxt-준수를-코드에-넣는다)에서 필터링을 제안한다.

**(3) 실제 요청은 Playwright 브라우저다.** 비로그인이고 사람이 읽는 페이지와 같은 것을 읽지만,
요청 간격 제어가 다른 수집기(더쿠·다음 카페의 `pause()`)만큼 명시적이지 않다.

### 4-5. 더쿠 — 회색지대, 의사결정 필요

- **코드**: [theqoo.ts](../apps/pipeline/src/collectors/theqoo.ts)
- **경로**: `https://theqoo.net/{게시판}?page=N` (정적 HTML, `fetch`. 브라우저 불필요)
  → 제목에 키워드가 걸린 글만 본문 추가 요청 (**한 번에 최대 30건 상한**)
- **저장**: 제목 + 본문 + 원문 링크

**실측 결과:**

| 항목 | 결과 |
|---|---|
| `https://theqoo.net/robots.txt` | **HTTP 404 — robots.txt가 없다** |
| 이용약관 페이지 | **없음.** `/terms` 404, `/policy`는 개인정보처리방침이고 자동 수집·크롤링 관련 조항이 없다 (55KB 전문에서 "크롤", "스크래핑", "자동화", "무단", "복제", "저작권", "API" 키워드 0건) |
| 통합검색 (`act=IS`) | **HTTP 403** |
| 게시판 한정 검색 | HTTP 200이지만 `search_keyword`를 무시하고 최신 목록을 반환 (검색이 사실상 동작하지 않음) |

#### 판단

**금지하는 문서가 없다.** robots.txt도 약관도 없다. 로그인 벽도 없고, 목록·본문 모두 비로그인으로 열린다.
[야놀자 형사 사건](#국내-판례가-그은-선)의 "회원 가입 없이 자유롭게 접근 가능, 별도 보호조치 없음" 조건에 해당한다.

**동시에 허용하는 문서도 없다.** "robots.txt가 없다 = 허용"은 RFC상 맞지만, 회사가 원한 "근거자료"로는 약하다.
그리고 **통합검색이 403이라는 것은 서버가 일부 자동 접근을 거부하고 있다는 신호**다
(우리 코드는 이 403을 우회하지 않고 목록 훑기로 우회 없이 대체했다 — 이건 좋은 정황이다).

#### 선택지

| 안 | 내용 | 장단 |
|---|---|---|
| **A. 끈다** | 설정에서 `theqoo` 제거 | 리스크 0. 하지만 **반응이 가장 많이 나오는 채널 하나를 잃는다** |
| **B. 운영자에게 서면 허가를 요청한다** ⭐ | 더쿠 운영진에 목적·수집량·용도를 밝히고 이메일 허가를 받아 이 문서에 첨부 | **회사가 요구한 "근거자료"의 가장 강한 형태.** 회신이 없거나 거부면 A로 간다 |
| **C. 현행 유지 + 최소 수집 원칙 명문화** | 요청 간격, 상한, 저장 범위, 403 시 즉시 중단을 문서와 코드로 고정 | 근거가 "금지 문서 부재"뿐이라 방어력이 B보다 약하다 |

**권고: B를 먼저 시도하고, 회신 전까지는 C의 조건으로 운영.** 공식 API가 없어 대체 경로가 없기 때문이다.

로그인 세션을 쓰지 않으므로 계정 리스크도, 보호조치 우회 문제도 없다. 요청 간격은 `pause()`로 제어된다.

### 이 전환의 손익

**✅ 이득이 크다.** 이 도구는 **자사 앱을 모니터링하는 것이 목적**이므로 "자사 앱만"이라는 제약이 사실상 제약이 아니다.
공식 API로 옮기면 robots.txt 문제가 **사라진다**. 무료다(개발자 계정에 이미 포함).

**DB 실측(2026-08-29)에서 현재 앱 리뷰 수집 대상은 전부 자사 앱이었다** (앱 4종 × 국가 4곳).
경쟁사 앱을 넣어 둔 것이 하나도 없으므로, **"자사 앱만"이라는 제약이 지금 수집량에 미치는 영향은 0이다.**

**오히려 늘어난다.** 현재 iTunes RSS는 페이지당 50건 × 3쪽이 상한인데, App Store Connect API는
200건씩 페이지네이션이 된다. 지금 앱스토어가 최근 30일 11건뿐인 것도 이 상한 때문일 가능성이 있다.

**⚠️ 잃거나 확인해야 하는 것 3가지:**

1. **앞으로도 경쟁사 앱 리뷰는 못 본다.** 지금은 안 보고 있지만, 나중에 요구가 생기면
   그건 **적법한 경로가 없는 요구사항**이라는 뜻이다. 요구사항 쪽을 조정해야 한다.
2. **구글플레이는 별점만 준 리뷰가 빠진다.** 다만 이 도구는 텍스트를 분류하므로 실질 손실이 작다.
3. 🔴 **자격증명이 한 벌로 끝나지 않는다. 이게 이 전환의 진짜 비용이다.**

   스토어 공개 정보로 확인한 결과(2026-08-29), 현재 수집 중인 앱 4종은
   **App Store Connect 기준 2개 판매자 계정, Play Console 기준 3개 개발자 계정**에 나뉘어 있다.
   자사 브랜드라도 법인이 갈리면 스토어 계정도 갈리기 때문이다(해외 법인 포함).

   | | 필요한 자격증명 |
   |---|---|
   | App Store Connect API | 판매자 계정마다 **.p8 개인키 + issuer ID + key ID** → **2벌** |
   | Play Developer API | 개발자 계정마다 **OAuth 서비스 계정** → **3벌** |

   **코드 작업은 "중"이지만 선행조건은 기술 문제가 아니라 조직 문제다.** 다른 법인 계정의 키는
   그 계정 관리자에게 발급을 요청해야 하고, 그 일정은 개발 쪽에서 통제할 수 없다.

   > 지금 스크래핑 방식이 편했던 이유가 정확히 이것이다. **앱 ID만 알면 계정 소유권과 무관하게
   > 전부 읽을 수 있었다.** 그 편의가 robots.txt 위반의 대가였다.

   → 수집기는 **서비스별로 다른 자격증명을 골라 쓸 수 있는 구조**여야 한다.
   전역 키 하나를 가정하고 만들면 두 번째 계정에서 다시 뜯어고쳐야 한다.

   (저장한 뒤 화면에서 안 보여주는 것과 법적으로 다르다)
2. **더쿠와 Threads가 이미 0으로 저장하고 있다.** 같은 방식을 나머지에 적용하면 된다.

3. **보유기간을 정한다.** 집계 결과는 남기고 원문은 지우는 방식이면 대시보드 기능을 잃지 않는다
4. 앱 리뷰를 **재연동할 때 처음부터 작성자명을 안 받게 만든다.** 나중에 지우는 것보다 싸다

## 7. 코드에 반영할 조치

현재 코드에는 **robots.txt를 읽거나 준수하는 로직이 전혀 없다** (`grep -rn "robots" apps/ packages/` → 0건).
"합법적으로 크롤링한다"고 말하려면 이게 있어야 한다.

### 7-1. 위반 경로를 끈다 (즉시)

```
X 경로 → api 로 고정                      (수집량 유지, 유료)
Threads → 끈 상태 유지                     (공식 API 권한 승인 전까지)
```

**둘 다 "끄고 끝"이 아니라 "적법한 경로로 갈아탄다"는 뜻이다.** 대체 경로는 [5절](#5-합법-대체-경로)에 있다.

### 7-2. robots.txt 준수를 코드에 넣는다

- 수집 시작 시 대상 호스트의 `robots.txt`를 받아 캐시하고, 요청 전 경로를 대조한다
- 차단된 경로면 요청하지 않고 그 사실을 수집 로그에 남긴다 (조용히 0건이 되면 안 된다)
- **디시**: 검색 결과에서 `gall.dcinside.com/robots.txt`가 Disallow한 갤러리(`id=47`, `cat`, `dog`,
  `stock_new`, `baseball_new8`, `m_entertainer1`, `produce48`, `singo` 등) 링크를 걸러낸다
- **Crawl-delay 존중**: x.com은 `Crawl-delay: 1`을 명시한다

### 7-3. User-Agent에 신원을 밝힌다

현재 더쿠·다음 카페 수집기는 **실제 브라우저 UA를 그대로 흉내 낸다**
([theqoo.ts:32](../apps/pipeline/src/collectors/theqoo.ts), [daum-cafe.ts:44](../apps/pipeline/src/collectors/daum-cafe.ts)).
기능상 이유가 있지만(다음은 모바일 UA여야 모바일 페이지를 준다), **"합법적 크롤링"의 통상적 예절은 신원을 밝히는 것**이다.
차단당하면 그건 거부 의사이므로 존중하면 된다 — 숨길 일이 아니다.

제안: 기존 UA 뒤에 식별자를 덧붙인다 (모바일 판별을 깨지 않으면서 신원을 남긴다).

```
Mozilla/5.0 (iPhone; ...) Safari/604.1 FeedbackRadar/1.0 (+연락처)
```

> 실제로 다음 카페가 모바일 페이지를 계속 주는지 실측 확인이 필요하다.

### 7-4. 저장 범위를 최소화한다

- 본문 전문이 아니라 **분류에 필요한 만큼만** 저장 (디시는 이미 800자 상한)
- 닉네임이 실제로 쓰이지 않는다면 저장하지 않는다
- 보유기간을 정하고 지난 원문은 지운다 (집계 결과는 남긴다)

### 7-5. 거부 신호를 우회하지 않는다 (현재 준수 중, 명문화)

- **403이 오면 그 경로를 그만 두드린다.** 더쿠 통합검색 403 → 우회 시도 없이 목록 훑기로 대체했다.
  다음 카페 403 게시판 → 세 번 겹치면 제목만 저장하고 본문 요청을 멈춘다 ✅
- **캡차 우회, 브라우저 지문 위조, IP 로테이션은 하지 않는다** (현재 없음) ✅
- **로그인 벽을 넘지 않는다** — X `web`만 예외이고, 그래서 끄는 것이다

## 8. 재확인 방법

robots.txt는 예고 없이 바뀐다. **6개월마다, 그리고 새 수집 소스를 추가할 때** 아래를 돌리고
이 문서의 실측일과 인용문을 갱신한다.

```bash
for u in https://theqoo.net/robots.txt https://m.cafe.daum.net/robots.txt https://cafe.daum.net/robots.txt https://search.dcinside.com/robots.txt https://gall.dcinside.com/robots.txt https://x.com/robots.txt https://www.threads.com/robots.txt https://play.google.com/robots.txt https://itunes.apple.com/robots.txt; do echo "=== $u ==="; curl -s -m 20 -w "\n[HTTP %{http_code}]\n" -A "Mozilla/5.0" "$u"; done
```

**확인 순서:**

1. HTTP 상태가 200인가 404인가 (404 = 규칙 없음)
2. `User-agent: *` 그룹에 우리 경로를 막는 `Disallow`가 있는가
3. 우리 UA 이름이 개별 그룹으로 지정돼 있는가
4. `Crawl-delay`가 있는가

## 10. 결정 기록 (2026-08-29)

**방침: 금지 문서가 있는 경로와 회색지대를 모두 끄고, 근거가 명확한 것만 남긴다.**

### 무엇을 껐나

운영 설정(`settings` 표의 `config.sources`)을 이렇게 바꿨다. 끈 것은 값을 지우지 않고
**명시적으로 `false`로 박았다.** 키가 없으면 프리셋이나 다른 머신이 다시 켤 수 있기 때문이다.

```
appstore    true   → false
googleplay  true   → false
threads     true   → false
x           (없음) → false
theqoo      (없음) → false
daum-cafe   (없음) → false
naver       true   → true    (유지)
dcinside    true   → true    (유지)
```

이 결정으로 무엇을 잃는지 숫자로 남긴다. **되돌릴 근거가 필요할 때 쓰라고 적는다.**

2. **X** — 심각 6건. 토큰만 있으면 코드는 이미 있다. 다만 유료다
3. **디시 완화 3건** — 유일하게 켜져 있는 커뮤니티라 **차단 갤러리 필터·HTTP 상태 확인·요청 간격 정비**의

4. **Threads** — 심각 1건. 리드타임이 가장 길고 얻는 것은 가장 작다

→ 각 전환의 상세는 [공식 API 전환 계획](official-api-migration.md).

| | 결정 당시 알던 것 | 확인 후 |
|---|---|---|
| **디시** | robots.txt `Allow: /` → 가장 근거가 강한 커뮤니티 | 🔴 **이용약관 제16조 ①이 사전 서면 동의 없는 크롤링을 명시적으로 금지** ([4-4](#4-4-디시인사이드--층위가-충돌한다)) |
| **더쿠** | 회색지대 | 🟡 그대로 — **금지 문서가 아예 없다**(robots.txt 404, 약관 페이지 없음) |

**"금지 문서가 있는 경로와 회색지대를 모두 끈다"는 방침을 그대로 적용하면, 지금 꺼야 하는 것은 디시다.**
그리고 그렇게 하면 **커뮤니티 채널이 0이 되고**, 30일 기준 수집량이 708건에서 178건으로,
심각 이슈는 4건에서 0건으로 떨어진다.

**선택지는 셋이다.**

| 안 | 내용 | 결과 |
|---|---|---|
| **A** | 디시도 끈다 | 방침에 일관. **커뮤니티 0, 심각 이슈 탐지 0** |
| **B** | 디시·더쿠 양쪽에 **서면 동의를 요청**하고 회신까지 현행 유지 | 디시는 제16조 ①이 요구하는 절차를 그대로 밟는 것이라 **가장 정공법**. 더쿠도 같은 문서로 처리 가능 |
| **C** | 디시만 유지 | 🔴 **권하지 않는다.** 명시적 금지 조항을 알고도 계속하는 것이 되어, 잡코리아 사건에서 불리하게 작용한 "알고도 우회" 유형에 가까워진다 |

**권고는 B였으나, 2026-08-30에 A로 결정했다.** 명시적 금지 조항이 있는 상태로 계속 도는 것을
허용하지 않는다는 방침이다. 디시를 껐고, **켜져 있는 소스는 네이버 하나만 남았다.**

### 최종 상태와 그 대가

| | 원래 | 디시·더쿠 제외 후 |
|---|---:|---:|
| 30일 수집량 | 1,181 | **178** (−85%) |
| 30일 부정 피드백 | 183 | **3** (−98%) |
| 30일 심각 이슈 | 31 | **0** (−100%) |

**심각 이슈 탐지가 0이다.** 적법성은 확보했지만 도구가 기능하지 않는다.
이 상태를 벗어나는 유일한 길은 [전환 계획](official-api-migration.md)의 실행이고,
그중 **앱 리뷰 두 소스가 가장 빠르다**(심각 10건, 외부 심사 없음, 자격증명만 필요).

### 서면 동의 요청은 여전히 열려 있다

디시 제16조 ①은 **"사전 서면 동의"**라는 경로를 스스로 명시한다. 더쿠도 운영진 허가가 유일한 복귀 경로다.
**두 곳에 같은 문서 한 벌로 요청할 수 있다** — 목적, 수집 범위, 요청 빈도, 저장 범위, 용도, 중단 요청 창구.
회신이 오면 그때 다시 켜면 되고, 그것이 회사가 요구한 "근거자료"의 가장 강한 형태이기도 하다.
요청서 항목은 [소스별 문서](sources/theqoo.md)에 적어 뒀다.

### 되돌릴 수 있는 여지

- **더쿠**: 접었지만 코드는 남아 있다. 운영진 서면 허가를 받으면 설정 한 줄로 되돌아온다.
  → [4-5](#4-5-더쿠--회색지대-의사결정-필요)의 B안
- **디시**: robots.txt가 명시적으로 `Allow: /`인 유일한 커뮤니티다.
  이것까지 접으면 커뮤니티 채널이 0이 되고, 그때는 이 도구가 앱 리뷰 + 블로그 모니터로 축소된다
