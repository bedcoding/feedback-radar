## 2. 채택 — 운영 중

### 2-1. 블루스카이 (AT Protocol)

| | |
|---|---|
| 경로 | `app.bsky.feed.searchPosts` (공식 API) |
| 비용 | **무료.** 읽기 과금이 없다 |
| 승인 | **불필요.** 무료 계정 + 앱 비밀번호 |
| 채택 이유 | **robots.txt가 자동 수집을 명시적으로 허용**하고 대량이면 API를 쓰라고 안내한다 |

> 🔵 **이 저장소에서 조사한 30여 곳 중 유일하게 수집을 권하는 문서다.**
>
> > Hello Friends! If you are considering bulk or automated crawling, you may want to look
> > in to our protocol (API), including a firehose of updates. ... By default, may crawl
> > anything on this domain.
>
> 다른 사이트들이 `ClaudeBot`·`GPTBot`을 이름으로 지목해 차단하는 것과 정반대다.
> 이용약관에도 크롤링 금지 조항이 없다. **층위 1·2·3이 모두 깨끗한 유일한 소스다.**

> 🔵 **해외 커버리지가 여기서 풀린다.** 적재된 1,131건의 언어 분포가
> **한국어 577건 대 해외 552건으로 거의 반반**이다 (영어 154 · 프랑스어 140 · 중국어 135 ·
> 스페인어 66 · 일본어 32 · 포르투갈어 23). 진출 시장과 겹친다.
> **6-3절이 "해외는 앱 리뷰뿐"이라고 판단했던 근거를 뒤집은 실측이다.**

> 🔵 **걷어낸 디시인사이드의 자리를 메운다.** 최근 90일 기준 블루스카이 706건·부정률 10.5%로,
> 적법 경로가 없어 뺀 디시인사이드(659건·12.3%)와 거의 같은 규모다. 신규 유입이 네이버
> 3채널(부정률 0~1%)뿐이던 상태에서 **실질 신호를 되찾은 채널이다.**

상세는 [`sources/bluesky.md`](sources/bluesky.md).

### 2-2. 네이버 검색 API (블로그 · 카페 · 뉴스)

| | |
|---|---|
| 경로 | NAVER API HUB 검색 API |
| 비용 | **무료.** 3채널이 **하루 25,000회를 공유** |
| 승인 | 불필요 (콘솔에서 즉시 발급) |
| 채택 이유 | 공식 API이고, robots.txt 적용 대상이 아니며, 로그인 벽·IP 차단을 넘지 않는다 |
| 남은 쟁점 | 이용약관 7.3 ③의 "저장(캐시 행위 포함)" 조항. 법무 검토 1순위 |

**채널별 실측 (2026-09-06, 같은 키로 호출)**

| 엔드포인트 | 응답 | 작성일 필드 |
|---|---|---|
| `blog` | 200 | ✅ `postdate` |
| `news` | 200 | ✅ `pubDate` (시각·오프셋까지) |
| `cafearticle` | 200 | ❌ **없음** |
| `kin` · `webkr` · `encyc` · `image` · `local` | **401** | 현재 키가 미구독 |

> ⚠️ **네이버 카페는 작성일을 구조적으로 못 받는다.** API 응답 필드가
> `title, link, description, cafename, cafeurl`뿐이다. 그래서 적재된 글의 `posted_at`이
> 비고, 기간 필터가 걸린 화면에서는 보이지 않는다. 코드 문제가 아니라 API의 한계다.

> 401이 뜬 채널들은 **승인 문제가 아니라 구독 문제**일 수 있다. 콘솔에서 추가 구독이
> 가능한지는 확인하지 못했다 → 7절.

> 🔴 **노이즈율이 채널마다 크게 갈린다** (2026-09-07 실측). 관련도 판정 기준으로
> **네이버 카페 52% · 블로그 34% · 뉴스 25%**다. 같은 키워드를 던지는 블루스카이는 14%,
> 앱 리뷰는 0%다. **검색 API로 넓게 긁는 방식 자체의 대가**이지 키워드 문제가 아니다.
> 화면에는 걸러진 뒤가 나오므로 보이지는 않지만, 분류 호출은 그만큼 더 나간다.
> `excludeHints`를 늘려 줄이려다 접은 경위는 [`sources/naver.md`](sources/naver.md) 1-3절.

## 3. 채택 — 코드 완료, 자격증명 대기

두 소스 모두 **자사 앱만** 읽을 수 있고 **비용이 없다.** 자격증명이 없으면 수집기가
스킵 로그를 남기고 빈 배열을 돌려주므로, 켜 둔 채로도 오류가 나지 않는다.

### 3-1. 앱스토어 리뷰 — App Store Connect API

| | |
|---|---|
| 예전 경로 | iTunes RSS (`itunes.apple.com/{국가}/rss/...`) |
| 왜 버렸나 | Apple robots.txt가 `Disallow: /*/rss/*`로 막아 둔 대상이었다. 2026-08 실측에서 리뷰를 아예 주지 않기 시작하기도 했다 |
| 필요한 것 | `ASC_KEY_<이름>_ISSUER_ID` / `_KEY_ID` / `_PRIVATE_KEY` (판매자 계정마다 1벌) |
| 발급 주체 | App Store Connect **Admin 이상** |

> 🟢 **전환하면 국가 커버리지가 넓어진다.** RSS는 국가별 주소라 한 국가씩 따로 긁어야 했고
> 실제로 `kr`만 설정돼 있었다. 공식 API는 **앱 단위로 출시된 전 국가 리뷰를 함께** 주고,
> 국가는 조회 조건이 아니라 각 리뷰가 들고 오는 값(`territory`)이다. 호출 수는 앱×국가에서
> 앱 하나로 줄고 국가 표기는 더 정확해진다.

**함정**: `.p8` 파일은 발급 시 **1회만** 내려받을 수 있다. 키 역할이 Customer Support면 403이 난다.

### 3-2. 구글플레이 리뷰 — Play Developer API

| | |
|---|---|
| 예전 경로 | `google-play-scraper` |
| 왜 버렸나 | 그 라이브러리가 두드리는 `play.google.com/_/PlayStoreUi/data/batchexecute`를 Google robots.txt가 `Disallow: /_`로 막는다. `/store/getreviews`도 별도로 차단돼 있다 |
| 필요한 것 | `GOOGLE_PLAY_SA_JSON` (서비스 계정 JSON 1벌) + **개발자 계정마다 권한 부여** |
| 발급 주체 | 개발이 GCP에서 생성 → Play Console **관리자**가 초대 |

> 🔵 **구글은 robots.txt를 약관 안으로 편입시켜 뒀다.** 보통 robots.txt는 기술적 신호라
> 법적 무게가 약한데, 구글 서비스 약관의 "Google 서비스 악용 금지" 조항이 이렇게 적혀 있다.
>
> > Google 웹페이지에서 자동화된 수단을 사용하여 컴퓨터가 읽을 수 있는 요청 사항
> > (**예: 크롤링, 학습 또는 기타 활동을 거부하는 robots.txt 파일**)에 위배되는 방식으로
> > Google 서비스의 콘텐츠에 접근하는 행위
>
> 그래서 **robots.txt 위반이 곧 계약 위반이 된다.** 층위 1(robots.txt)과 층위 2(약관)가
> 여기서는 분리되지 않는다. 이 저장소에서 판정 근거가 가장 강한 차단 사례다.
> 영문 원문과 상세는 [`sources/googleplay.md`](sources/googleplay.md) 2-2절.

**함정**: 필요한 권한 이름이 **"리뷰 답글(Reply to reviews)"**이다. 읽기인데 답글 권한을
요구하는 구조라, "앱 정보 보기"만 받으면 403이 난다.

> 🔴 **전환하면 국가 축을 잃는다.** Play Developer API에는 country 파라미터가 **없다.**
> 응답의 `reviewerLanguage`는 언어이지 국가가 아니라 대체재로 쓸 수 없다.
> 기존에 적재된 국가별 데이터(전체 기간 `us` 427 · `fr` 203 · `jp` 116)는 남지만,
> **이후 들어오는 리뷰는 전부 국가가 빈다.**

> 🔴 **최근 7일 안에 작성·수정된 리뷰만 온다.** 과거 백필이 불가능하고, 스케줄러가
> 일주일 넘게 멈추면 그 구간은 영구 유실이다. 과거분은 Play Console CSV로 따로 채운다.

## 4. 미채택 — 사유별

### 4-1. 적법 경로가 없다

| 플랫폼 | 근거 | 대체 경로 |
|---|---|---|
| **디시인사이드** | robots.txt는 `Allow: /`지만 **이용약관 제16조 ①이 사전 서면 동의 없는 크롤링을 명시적으로 금지** | 공식 API 없음 |
| **더쿠** | 금지 문서도 **허용 문서도 없다.** 근거가 "금지 문서 부재"뿐이라 도입 승인용으로는 약하다 | 공식 API 없음 |
| **네이트판** | robots.txt `User-agent: *` → `Disallow: /` (명명된 검색봇 8종만 예외) | 없음 |
| **에펨코리아** | `*`는 `Disallow: /` 후 `/best`·`/humor`만 개방. **목록은 열고 본문은 막는 배치** | 없음 |

> 이 넷이 **수집량의 대부분을 차지했다.** 90일 기준 디시 659건(33.8%) + 더쿠 506건(25.9%)만으로
> 전체의 **59.7%**다. 여기에 Threads 132건을 더하면 **66.4%**를 걷어낸 셈이다.

### 4-2. 외부 승인·심사가 필요하다

| 플랫폼 | 무엇이 필요한가 |
|---|---|
| **Threads** | 법인 비즈니스 인증 + 앱 심사(3단계). 공식 `keyword_search` 엔드포인트는 존재하지만 승인 없이는 못 쓴다 |
| **Reddit** | 2026-06-05부터 **Responsible Builder Policy**로 신규 OAuth 클라이언트가 전부 수동 승인 대상(대기 2~4주). 게다가 브랜드 모니터링은 **상업적 이용**으로 분류돼 무료 등급 대상이 아니다 |

> **판단**: 내부 공모전 단계에서 외부 기업에 심사를 신청하는 것은 명의가 애매하다.
> 정식 채택 이후 회사 명의로 신청하는 것이 맞다. 발표에서는 "이런 이유로 뺐고,
> 필요하면 승인을 받아 켤 수 있다"로 설명한다.

**Threads를 뺀 실익 근거** — 90일 실측에서 심각 이슈 **1건**이었다. 3단계 심사 비용에 비해 값이 작다.

### 4-3. 유료다

| 플랫폼 | 비용 |
|---|---|
| **X `api`** | 포스트 읽기 **1건 $0.005**, 사용자 읽기 1건 $0.010. 저장 0건이어도 읽은 만큼 과금 (단 같은 UTC 하루 내 같은 포스트 재조회는 재과금 없음) |

> ⛔ **X `web` 경로는 쓰지 않는다.** 비용이 0원이라 기본값처럼 보이지만
> robots.txt가 `Disallow: /`이고, 이용약관이 crawling/scraping을 명시적으로 금지하며,
> 저장한 로그인 쿠키로 로그인 벽을 넘는다. 세 층위에 모두 걸린다 → `sources/x.md` 2-4절

### 4-4. 적법하지만 실익이 없다

**다음 카페** — 이 저장소에서 가장 역설적인 사례다.

| 층위 | 판정 |
|---|---|
| robots.txt | 🟢 **명시적 허용.** `cafe.daum.net`이 `bbs_list`·`bbs_read`를 `Allow`로 열어 둔다 |
| 계약·약관 | 🟢 **제약 없음** — 웹 직접 파싱에는 동의한 계약 자체가 없다 |
| 개인정보 | 🟢 닉네임 저장을 제거했다 (2026-09-06) |
| **실익** | 🔴 **없다** |

> 🔵 **"공식 API = 안전"이 성립하지 않는 유일한 반례.**
> 카카오 검색 API로 옮기면 **REST 키를 발급받는 행위가 곧 운영정책 동의**이므로
> 제5조 20호(목적 외 캐시·미갱신)·30호(사전 승낙 없는 복제)가 새로 걸린다.
> 즉 **공식 API 쪽이 더 불리하다.**

**실익이 없는 이유 — 사슬로 물려 있다**

| 단계 | 사실 |
|---|---|
| robots.txt가 `/_search`를 막는다 | → 검색을 쓸 수 없다 |
| 게시판 훑기만 가능 | → 페이지를 못 넘겨 **게시판당 20건이 상한** |
| 주제가 맞는 게시판은 **달글 구조** | → 제목이 스레드 이름이라 서비스명이 안 나온다. 실제 반응은 댓글에 있는데 수집기는 본문만 본다 |
| 구조가 맞는 게시판은 | 주제가 안 맞거나 20건이 **1분치**다 |

한 카페(비로그인으로 보이는 게시판 4개) 실측:

| 게시판 성격 | 형식 | 20건이 덮는 기간 | 판정 |
|---|---|---|---|
| 웹툰/소설/애니 달글 | 달글 | 12일 | 주제 O / 구조 X |
| 잡담 | 개별 글 | 10일 | 구조 O / 주제 X |
| 펌·유머 | 개별 글 | 35분 | 구조 O / 주제 X |
| 자유게시판 | 개별 글 | **1분** | 구조 O / 속도 X |

수집을 실행하면 정상 동작한다(`20건 훑어 0건`). 파싱도 날짜도 문제없다.
**제목 필터에 걸리는 글이 없을 뿐이다.**

### 4-5. 수집 대상의 성격이 다르다

**블라인드** — robots.txt만 보면 오히려 열려 있다(`/user/history`와 `/search/`만 차단).
막는 것은 기술이 아니라 성격이다.

| | |
|---|---|
| 이 도구가 집계하는 것 | 이용자의 **서비스 불만** |
| 그 플랫폼에 있는 것 | 재직자의 **회사 이야기** |

집계 대상이 서비스가 아니라 사람이 되고, 그러면 이것은 수집 적법성 문제가 아니라
다른 종류의 사안이 된다. **법 이전에 넣지 않는 것이 맞다.**

### 4-6. 서비스가 종료·차단됐다

해외 커뮤니티를 보려면 전 세계 웹을 색인하는 검색 API가 필요한데,
**2025~2026 사이에 전부 막혔다.**

| API | 상태 | 확인일 |
|---|---|---|
| Google Custom Search JSON | **신규 고객 차단** + 2027-01-01 종료. 공식 문서 원문: "The Custom Search JSON API is closed to new customers." | 2026-09-06 |
| Bing Search API | **2025-08-11 완전 폐지.** 신규 가입 중단, 기존 인스턴스도 해체 | 2026-09-06 |
| Brave Search API | 2026 초 **무료 티어 폐지.** 신규는 월 $5 크레딧 + 카드 필수, 지출 상한 없음 | 2026-09-06 |

> **서드파티 SERP API**(SerpApi, Firecrawl 등)에는 무료 티어가 남아 있지만, 결국
> 검색엔진을 대신 긁어주는 중개 서비스다. 직접 하지 않기로 한 일을 돈을 주고 남에게
> 시키는 구조라 적법성 관점에서 개선이 아니다.

### 4-7. 한도가 실용성을 넘지 못한다

| 플랫폼 | 한도 |
|---|---|
| **유튜브 Data API** | 승인 불요·무료지만 `search.list`가 **하루 100회** 전용 버킷. 키워드 9개 기준 하루 11회 수집이 상한이고, 영상 검색 → 댓글 조회 2단계라 실제로는 더 빡빡하다 |

## 5. 검토했으나 신호가 없어 보류

국내 커뮤니티 10곳의 robots.txt를 직접 받아 확인했다 (2026-09-06).
**허용 여부와 신호량이 정확히 반비례한다.**

| 사이트 | `User-agent: *` 판정 | 우리 신호 |
|---|---|---|
| 뽐뿌 | 🟢 `Allow: /zboard/` — 게시판을 **명시적으로 개방** | 거의 없음 |
| 인스티즈 | 🟢 `*` 구간이 **아예 없음** (AI 봇 24종만 지목 차단) | 얇음 |
| 클리앙 | 🟢 robots.txt 부재 | 얇음 |
| 인벤 | 🟢 특정 게임 보드만 차단 | 없음 (게임) |
| 브런치 | 🟡 `*` 허용, `/search`·`/feed`만 차단 | 창작자 글이지 독자 반응이 아님 |
| 루리웹 | 🟠 `/*view=`·`/*cate=` 차단 (글 읽기 경로) | 있음 |

> **패턴 하나**: 조사한 거의 모든 사이트가 `ClaudeBot`·`GPTBot`·`anthropic-ai` 등
> AI 크롤러를 **이름으로 지목해 차단**한다. 한 곳은 주석에 의도를 그대로 적어 뒀다 —
> "AI 학습/스크랩 봇 차단 (검색 색인용 크롤러는 차단하지 않음)".
> 이 도구의 수집기는 그 이름들이 아니지만, **수집한 글을 LLM에 넣어 분류**한다.
> `*` 규칙만 보면 통과해도 운영자가 표명한 의사는 그 용도를 겨냥하고 있다.
> 부정경쟁방지법 (파)목은 운영자의 표명 의사를 따지므로, `*`가 열려 있다는 것만으로
> 안심할 근거가 되지 않는다.

> **구조적 결론**: 트래픽이 크고 데이터 가치가 높은 커뮤니티일수록 스스로 막고,
> 작은 곳은 신경 쓰지 않는다. 그래서 **"허용된 곳을 더 찾는" 방향으로는 신호가 늘지 않는다.**

## 8. 이 기록을 어떻게 쓰나

- **도입 검토 시**: 1절 표에서 결정을 보고, 사유가 필요하면 4절, 원문이 필요하면 `sources/`로 내려간다.
- **채널을 다시 켤 때**: 그 플랫폼의 미채택 사유가 해소됐는지 먼저 확인한다.
  사유가 "승인 필요"였다면 승인 주체가 바뀌었는지, "실익 없음"이었다면 대상 게시판이 바뀌었는지다.
- **새 플랫폼을 검토할 때**: 5절의 구조적 결론을 먼저 본다.
  **허용 여부보다 신호량이 먼저다.** 열려 있어도 신호가 없으면 빈 통이 늘 뿐이다.
