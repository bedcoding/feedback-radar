# Feedback Radar 📡

외부 채널(앱스토어, 구글플레이, 네이버, 커뮤니티, SNS)에 흩어진 서비스 사용자 반응을 주기적으로 수집하고,
LLM이 건별 분류(감성/카테고리/심각도/담당팀)한 뒤 **급증 감지 + 원문 링크가 달린 브리핑**을
대시보드와 파일로 내보내는 사용자 피드백(VOC) 모니터링 도구.

- **올인원 로컬 실행**: `npm run dev` 하나로 대시보드 + 스케줄러가 함께 뜹니다. 24시간 켜 두는 PC 한 대면 충분
- **API 키 없이 동작**: 머신에 [Claude Code](https://claude.com/claude-code)가 로그인돼 있으면
  구독 요금으로 태깅합니다 (`claude -p` 배치 호출). 없으면 API 키 → 키워드 휴리스틱 순으로 폴백
- **설계 원칙 "숫자는 코드가, 판단은 LLM이"**: 집계, 급증 감지는 SQL, LLM은 건별 분류만.
  리포트의 모든 인용에는 원문 링크가 붙습니다

## 화면

| 경로 | 용도 |
|---|---|
| `/` | 대시보드: 수집 현황, 수집 주기 설정, "지금 실행" |
| `/?service=<서비스명>` | 그 서비스만 (칩으로 고르면 URL이 이렇게 됩니다) |
| `/?filter=irrelevant` | 무관 판정으로 걸러진 글 (판정이 맞는지 검증용) |
| `/?period=7d` | 작성일 기준 최근 7일 (`today`, `7d`, `30d`, `all`) |
| `/?page=2` | 목록 2쪽 (한 쪽 50건) |
| `/tour` | **둘러보기**: 실제 UI 위에 설명을 얹는 제품 투어. 데모용 예시 데이터라 클론 직후에도 그대로 동작 |
| `/?tour=1` | 같은 설명을 **실데이터 화면** 위에 얹습니다 (발표용) |

- 투어는 `←` `→`로 넘기고 `Esc`로 닫습니다. **DB를 읽지 않고 예시 데이터로 동작**하므로 아직 한 번도
  수집하지 않은 머신에서도 화면이 똑같이 나옵니다 (서비스명만 설정에서 가져오고, 설정이 없으면 자리표시자)
- 투어 화면의 [PDF 만들기] 또는 `npm run deck`으로 전 단계를 PDF 한 벌로 굽습니다
- 서비스 칩, 탭, 쪽은 서로를 지우지 않고 조합됩니다 (서비스 하나를 고른 채 걸러진 글 탭으로 넘어가도 서비스가 유지됨).
  서비스를 고르면 목록뿐 아니라 **상단 통계와 카테고리 표까지 같이** 그 서비스 기준으로 바뀝니다

## 구조

```
feedback-radar/
├─ .env                                # 🔒 API 키, DB 접속 정보 (gitignore)
├─ private/                            # 🔒 비공개 파일 전용 (gitignore): 설정, DB, 리포트, 캡처
│   ├─ feedback-radar.config.json      #    테넌트 설정의 최초 씨앗 (이후 원본은 DB)
│   ├─ reports/YYYY-MM-DD.md           #    일일 브리핑 보관
│   └─ deck-assets/tour-deck*.pdf      #    둘러보기를 구운 PDF
├─ .env.example                        # 환경변수 템플릿 (추적되는 유일한 .env 계열 파일)
├─ feedback-radar.config.example.json  # 설정 템플릿
├─ packages/core/          # DB(PostgreSQL), 택소노미, 태거 3종, 리포트 생성
├─ apps/pipeline/          # 수집기 + 스케줄러 + PDF 스크립트
└─ apps/web/               # Next.js 대시보드 + 둘러보기
```

**테넌트 설정의 원본은 DB다.** 화면에 뜨는 이름과 키워드, 앱 ID, 용어 사전은 `settings` 표의
`config` 키에서 읽습니다. 어느 머신에서 고쳐도 즉시 다른 머신과 배포본에 반영됩니다.
저장소 코드에는 서비스명이 하드코딩된 곳이 없고, 설정을 못 찾으면 `{서비스명}` 자리표시자를 보여줍니다.

`private/feedback-radar.config.json`은 **최초 씨앗**입니다. DB에 설정이 아직 없을 때 한 번 옮겨
심는 용도이고, 그 뒤로는 읽히지 않습니다. 새 머신에서는 이 파일 없이 DB 접속 정보만 있으면 됩니다.

수집 소스 (설정으로 켜고 끔):

| 소스 | 방식 | 안정성 |
|---|---|---|
| 앱스토어 리뷰 | iTunes RSS API (공식, 무인증) | ★★★ |
| 구글플레이 리뷰 | google-play-scraper | ★★★ |
| 네이버 블로그/카페 | 네이버 오픈 API (무료 일 25,000회) | ★★★ |
| 디시인사이드 | Playwright 통합검색 | ★★ |
| Threads | Playwright (실험적) | ★ |
| X(트위터) | 로그인 세션 + Playwright, 또는 X API v2 (**기본 꺼짐**) | ★ / ★★★ |
| 더쿠 | 게시판 목록 훑기 (검색이 없어 제목으로 거릅니다, **기본 꺼짐**) | ★★ |
| 다음 카페 | 게시판 목록 훑기 (모바일 경로, 게시판당 최신 20건, **기본 꺼짐**) | ★★ |

### X는 경로가 두 개다

수집량 카드의 `X 경로`에서 고릅니다. 성격이 정반대라 기본값을 정하는 대신 고르게 했습니다.

| 경로 | 비용 | 리스크 |
|---|---|---|
| `web` (기본) | **0** | 계정 정지, 구조 변경으로 조용히 0건이 될 수 있습니다 |
| `api` | 읽기 1건당 $0.005 | 없음 (약관 안, 안정적) |

**`web`은 저장해 둔 로그인 세션으로 검색 페이지를 읽습니다.** X는 비로그인 검색을 막아 뒀기 때문에
사람이 한 번 직접 로그인해 세션을 저장해야 합니다.

**설정 탭의 `X 세션` 칸에 쿠키를 넣으면 끝납니다.** 평소 쓰는 브라우저에서 x.com에 로그인한 뒤
개발자도구 → Application → Cookies → `https://x.com` → `auth_token` 값을 복사해 붙여넣고 저장합니다.
계정을 바꿀 때는 [세션 지우기]를 누르고 새 값을 넣습니다.

- 입력칸은 저장된 값을 되돌려 주지 않습니다(계정 접근권입니다). 저장 여부와 저장 시각만 보여줍니다
- 빈 칸으로 저장하면 기존 세션이 유지됩니다. 지우는 것은 [세션 지우기] 버튼만 합니다
- 세션은 `private/x-session.json`에 저장되고 git에는 올라가지 않습니다

터미널로 하고 싶으면 두 가지가 더 있습니다. 화면을 띄우기 어려운 환경에서 씁니다.

```bash
npm run x-login -- --cookie   # 쿠키 붙여넣기 (인자로 받지 않아 셸 히스토리에 남지 않는다)
npm run x-login               # 창을 띄워 직접 로그인
```

> **창을 띄우는 쪽에서는 [Google로 계속]이 작동하지 않습니다.** 자동화 브라우저라 구글이 OAuth를
> 거부합니다(X가 아니라 구글이 막는 것이라 계정을 바꿔도 같습니다). 소셜 로그인으로 가입한 계정은
> 쿠키를 넣는 방법을 쓰면 됩니다.
>
> 어느 경로든 `auth_token`이 없으면 저장을 거부합니다. 빈 세션이 저장돼 다음 수집에서야
> 알게 되는 일을 막습니다.

> **`web`은 X 약관이 금지하는 자동 수집에 해당하고, 계정이 정지될 수 있습니다.** 그래서 **버리기 쉬운
> 임시 계정으로 쓰는 것을 전제로 만들었습니다.** 개인 계정이나 업무 계정을 넣지 마라.
>
> 이 경로의 실패는 예외가 아니라 **조용한 0건**입니다. 그대로 두면 "글이 없어서 0건"과 구별되지 않아
> 몇 주 뒤에 압니다. 그래서 매 실행마다 막힌 사유(세션 없음, 로그아웃, 호출 한도, 계정 제한, 구조 변경)를
> 판별해 수집량 카드에 배너로 띄웁니다. 계정을 바꿔 다시 로그인하면 배너가 사라집니다.
>
> 요청 간격은 사람이 쓰는 속도를 넘지 않게 띄우고 키워드 순서도 매번 섞습니다. 균등 랜덤이 아니라
> **짧은 간격이 대부분이고 간헐적으로 크게 쉬는 분포**를 씁니다(균등 랜덤은 평균 근처에 몰려서
> 그 일정함이 오히려 기계의 특징입니다). 브라우저 지문 위조나 캡차 우회는 하지 않습니다.
>
> **속도는 수집량 카드의 `X 간격`에서 정합니다.** 값 두 개입니다.
>
> | 값 | 뜻 | 기본 |
> |---|---|---|
> | 간격(초) | 키워드 사이 **하한**. 상한은 그 2.4배이고, 페이지를 읽는 시간과 스크롤 간격도 여기서 파생됩니다 | 8 |
> | 긴 휴식(%) | 간격 대신 상한의 2~6배를 쉴 확률. **편차**를 정하는 값입니다 | 15 |
>
> 기본값이면 대부분 8~19초, 15% 확률로 38~115초 쉬고 한 번 수집이 약 7분입니다. 화면이 그 범위와
> 예상 소요를 같이 보여주므로 값을 올린 대가가 눈에 보입니다(20초/30%면 약 24분). 긴 휴식을 0으로
> 두면 간격이 늘 비슷해져 오히려 눈에 띄는데, 그 경고도 같은 자리에 뜹니다.
>
> **다만 간격보다 총량이 더 중요합니다.** 주기를 1시간으로 두면 키워드 9개 기준 하루 216번 검색이고,
> 간격을 어떻게 다듬어도 그건 사람의 사용량이 아니다. 계정을 오래 쓰려면 주기를 넉넉히(6시간 이상)
> 두고 키워드를 줄이는 편이 훨씬 효과가 큽니다.

**`api`는 공식 X API다.** 2026년 2월부터 무료 등급이 없어져 신규 발급은 종량제뿐이고, 읽기 1건에
$0.005다(1,000건당 $5). 저장 단계에서 중복이 걸러져 0건이 남아도 읽은 만큼은 청구됩니다.

> 브레이크가 두 개입니다. **회당 상한**(`xPosts`)이 한 번에 쓸 금액을, **월 예산**(기본 $50)이 총액을 막습니다.
> 회당 상한만으로는 총액이 정해지지 않기 때문입니다. 총액은 상한 × 실행 횟수이고, 주기를 줄이면
> 몇 배가 됩니다. 월 예산에 닿으면 그 달의 남은 실행에서 X만 건너뜁니다(다른 소스는 그대로 돕니다).
> 수집량 카드가 이번 달 사용액과 **지금 주기로 계속 돌 때의 월 환산액**을 같이 보여줍니다.
> X 개발자 포털에도 청구 주기당 지출 한도가 있습니다(마이그레이션 계정 기본 $400). 그건 마지막 방어선이고,
> 월 예산은 그 앞에서 호출 자체를 멈춥니다.
>
> 페이지를 넘기지 않도록(`next_token` 무시) 구현해 키워드당 상한 한 번이 최대치입니다.

배포판(Vercel)에는 Chromium이 없어 `web`을 쓸 수 없습니다. 그쪽은 `api`로 고정됩니다.

### 더쿠는 검색이 아니라 목록을 훑는다

**게시판 한정 검색이 `search_keyword`를 무시합니다.** 200을 주면서 최신 목록을 그대로 돌려줍니다
(2026-08 실측: 검색어를 바꿔도, 없는 단어를 넣어도 결과가 목록과 같았습니다). 통합검색은 403입니다.

그래서 게시판을 지정해 **목록을 페이지 단위로 훑고 제목에서 키워드를 거릅니다.** 설정의
`theqooBoards`에 게시판 이름(URL의 mid 값)을 넣어야 돌고, 비우면 건너뜁니다. 업종마다 볼 곳이
달라서 코드에 넣지 않았습니다.

| 성질 | 내용 |
|---|---|
| 브라우저 | **불필요.** 정적 HTML이라 fetch만 씁니다 (디시, Threads와 다릅니다) |
| 놓치는 것 | 본문에만 서비스명이 있는 글. 목록에는 제목만 옵니다 |
| 본문 | 제목이 걸린 글만 추가로 읽습니다 (한 번에 최대 30건) |
| 상한 단위 | 건수가 아니라 **쪽수**. 값을 키우면 더 오래된 글까지 내려갑니다 |

활발한 게시판은 43분에 20건씩 올라옵니다(실측). 수집 주기가 길면 쪽수를 늘려야 그 사이 글을
다 봅니다. 실측으로 3쪽(51건)에서 키워드가 걸린 글 15건이 나왔습니다.


### 다음 카페는 모바일 경로로만 보인다

**데스크톱은 비로그인에게 목록을 주지 않습니다.** `bbs_list`가 HTTP 200에 88KB를 돌려주는데
글 링크가 0건이고 `MEMBER_ROLENAME: "비회원"`만 들어 있습니다(2026-08 실측, 한 카페의 게시판
7개 전부). 모바일(`m.cafe.daum.net/{카페}/{게시판}`)은 같은 게시판을 비로그인으로 내려줍니다.
로그인 세션이 필요 없어서 X와 달리 계정 리스크가 없습니다.

목록이 Vue로 렌더되지만 **브라우저는 필요 없습니다.** 화면을 그리기 전의 데이터가
`articles.push({ dataid, title, writerNickname, articleElapsedTime, ... })` 형태로 HTML에
인라인되어 있어서, 오히려 파싱하기 쉽습니다. 본문은 글 상세의 `tx-content-container`에서 읽습니다.

| 성질 | 내용 |
|---|---|
| 브라우저 | **불필요.** 인라인 데이터를 파싱합니다 |
| 상한 | **게시판당 최신 20건.** `?page=2`가 무시되고 스크롤로도 더 안 나옵니다 |
| 게시판 고르기 | 글이 몰리는 종합 게시판은 20건이 **1~2분 분량**입니다(실측: 분당 19건). 주제별 게시판은 같은 20건이 **며칠에서 몇 주**를 덮습니다(실측: 11일, 25일) |
| 본문이 막힌 게시판 | 댓글로 대화하는 형식은 글 상세가 403입니다. 세 번 겹치면 그 게시판은 제목만 저장합니다 |
| 설정 | `daumCafeBoards`에 `카페아이디/게시판아이디`를 넣습니다. 비우면 건너뜁니다 |

과거 글까지 필요하면 이 경로로는 닿지 않습니다. 카카오 검색 API(`/v2/search/cafe`, 일 30,000회
무료)가 키워드 검색과 페이지 넘기기를 지원하지만, 특정 카페만 골라 볼 수는 없습니다.

### 브리핑 날짜는 작성일 기준이다

**수집일이 아니다.** 앱 리뷰는 오늘 수집해도 작성일이 몇 달 전이라, 수집일로 묶으면 오래된 글이
오늘 여론으로 집계됩니다. 실측(2026-08-20)에서 그날 브리핑 275건 중 46건이 2025년 글이었습니다.
첫 수집날에는 11년치가 한 덩어리로 들어갑니다.

그래서 브리핑, 카테고리 집계, 급증 기준선을 모두 `posted_at`으로 맞췄습니다. 한쪽만 바꾸면
'그날 작성된 글'과 '직전 며칠에 수집된 글'을 비교하게 되어 급증 판정이 어긋납니다.

| 성질 | 내용 |
|---|---|
| 여러 날짜가 갱신됩니다 | 한 번 수집해도 작성일이 흩어져 있어 그 날짜들의 요약이 낡습니다. 파이프라인이 이번 실행에서 들어온 글의 작성일만 골라 다시 만듭니다 |
| 작성일 없는 글 | 어느 날짜에도 안 들어갑니다(카페 API가 안 주는 경우 등). 그 건수를 화면과 브리핑에 적습니다 |
| 날짜 선택 | 최근 7일은 버튼, 그 앞은 달력. 달력은 `datalist`로 **데이터가 있는 날짜만** 후보로 줍니다 |

**요약은 글이 많은 날에만 만듭니다.** 요약은 다 읽을 수 없을 때 쓰는 압축이라, 몇 건뿐인 날에
만들면 원문보다 정보가 줄고 호출만 나갑니다. `SUMMARY_MIN_ITEMS`(11) 미만인 날짜는 화면이
원문을 그대로 싣습니다(스크롤 영역). 실측에서 날짜 1,057개 중 1,033개가 그쪽이라, 전부 요약하면
5,245회였던 호출이 85회로 줄었습니다.

과거 날짜를 채우려면:

```bash
npm run backfill                 # 무엇을 만들지 보여주기만 한다
npm run backfill -- --apply      # 요약이 없는 날짜만 만든다
```

이미 있는 날짜는 건너뛰므로 중간에 멈춰도 다시 돌리면 이어서 합니다. 프롬프트를 고쳐 다시
만들려면 `--force`를 붙입니다.

### 브리핑은 시간대 집중을 맨 위에 둔다

**급증 감지가 두 가지를 놓쳤습니다.** 기존 판정은 '직전 7일 평균 대비 3배 + 최소 5건'을
**카테고리별, 하루 단위**로 봅니다.

- 하루가 끝나야 판정되므로 배포 직후 몇 시간에 몰리는 반응은 당일에 안 보입니다
- 같은 사건이 카테고리 셋으로 갈리면 어느 쪽도 임계를 못 넘습니다

그래서 시간 축과 주제 묶음을 따로 둡니다. 실측(2026-08-20)에서 한 기능 개편 반응이 이렇게 잡혔습니다.

```
## 🔴 시간대 집중
- **12시~14시에 80건** (하루 평균 대비 2.8배, 그날의 35%, 부정 15건)
  - `서재` 7건 (부정 2)
    - "서재에서 소장작품까지 두 번 눌러야 해 불편하다는 개선 요청" (X) [원문](...)
```

판정은 **비율이 아니라 균등 분포 대비 배수**다. 위 사례는 그날 231건 중 80건이라 비율로는
35%여서, '그날의 50% 이상' 같은 문턱을 두면 놓칩니다. 평소 언급량이 많을수록 비율은 낮게 나옵니다.

주제어에서는 판정 어휘(`불만`, `요청`)와 검색 키워드를 뺍니다. 안 빼면 상위가 그 말들로 채워져
무슨 일인지 알 수 없습니다. 작성 시각이 없는 글은 이 집계에서 빠지고, 그 건수를 함께 표시합니다.

### 지원하지 않는 소스와 이유

주요 SNS를 직접 방문 테스트(2026-07)한 뒤 아래 소스들은 **의도적으로 배제**했습니다:

| 소스 | 배제 이유 |
|---|---|
| 인스타그램 | 검색, 해시태그 페이지가 로그인 필수 (로그인 페이지로 리다이렉트) |
| Bluesky | 로그아웃 상태에서 검색 기능 자체가 비활성화 |
| 페이스북 | 검색이 로그인 전용이거나 비공개 |

다음 카페는 처음에 이 목록에 있었습니다. 데스크톱 페이지가 로그인 벽으로 보였기 때문인데,
2026-08 재조사에서 **모바일 경로는 비로그인으로 열립니다**는 것을 확인해 지원 소스로 옮겼습니다
(위의 '다음 카페는 모바일 경로로만 보입니다' 참고).

원칙: **기본은 공식 API와 비로그인 공개 페이지만 씁니다.** 로그인 계정으로 우회하면 약관 위반이고,
계정 정지 하나로 파이프라인이 멈춥니다. Threads는 비로그인 상태에서도 검색 결과가 렌더링되는 것이
확인되어 실험적으로 지원합니다.

**X의 `web` 경로는 그 원칙의 의도된 예외입니다.** 위 소스들과 달리 X는 장애 발생 시 반응이 가장 먼저
올라오는 채널이라, 무료로 볼 수 있으면 값이 크다는 판단이었습니다. 예외로 두면서 세 가지를 지켰습니다.

- **임시 계정 전제.** 정지되면 그 계정만 버립니다. 개인 계정이나 업무 계정을 쓰지 않습니다.
- **리스크를 감추지 않습니다.** 막힌 사유를 판별해 화면에 띄웁니다. 조용한 0건으로 끝나지 않게 하는 것이
  이 예외를 감당할 수 있게 만드는 조건입니다.
- **돈이 필요하면 `api`로 바꿀 수 있습니다.** 예외가 유일한 선택지가 아니어야 합니다.

상용 운영이라면 `api`를 쓰는 게 맞습니다. `web`은 임시 프로젝트에서 비용 0을 유지하려고 리스크를
받아들이는 선택입니다.

## 2. 프리셋으로 설정 만들기 (한 줄)

`private/`는 gitignore라 클론 직후에는 **없습니다.** 아래 명령이 폴더를 만들고
업종 프리셋과 `.env` 템플릿을 복사합니다. **이미 있는 파일은 덮어쓰지 않습니다.**

```bash
npm run setup -- --list           # 어떤 프리셋이 있는지 보기
npm run setup -- content-platform # 프리셋 골라 셋업 (생략하면 content-platform)
```

| 프리셋 | 대상 |
|---|---|
| `content-platform` | 연재형 콘텐츠 플랫폼: 회차 단위 소비, 자체 재화 결제 |
| `commerce` | 쇼핑몰, 마켓플레이스: 주문, 배송, 반품 중심 |
| `saas` | 구독형 앱, SaaS: 요금제, 계정 관리 중심 |

프리셋에는 **업종 용어 사전(`domainPrompt`, `categoryKeywords`, `relevanceHints`)이 이미 들어 있습니다.**
새 머신에서 이걸 다시 기억해 낼 필요가 없다는 뜻입니다.

## 3. 설정에서 3가지만 채우기

`private/feedback-radar.config.json`을 열어 **아래 3개만** 본인 서비스에 맞게 바꾸면 됩니다.
첫 실행 때 이 값이 DB로 한 번 옮겨지고, 그 뒤로는 DB가 원본입니다 (화면에서 고치면 DB에 저장됩니다).

```jsonc
{
  "displayName": "우리 서비스",          // ← 화면, 리포트에 표시될 이름
  "keywords": ["서비스명", "줄임말"],     // ← 웹에서 검색할 키워드 (별칭, 오타 변형 포함)
  "appstore":   { "appId": "123456789" },              // ← 앱스토어 숫자 ID
  "googlePlay": { "appId": "com.example.app" }         // ← 구글플레이 패키지명
}
```

**앱 ID는 아래 명령으로 찾을 수 있습니다** (양쪽 스토어를 동시에 검색해 후보를 출력합니다):

```bash
npm run find-app -- "서비스명"
```

직접 찾으려면 앱스토어는 `apps.apple.com/kr/app/이름/id`**`1234567890`** 의 숫자,
구글플레이는 `play.google.com/store/apps/details?id=`**`com.example.app`** 부분입니다.
- 나머지 항목은 프리셋 값을 그대로 쓰면 되고, 필요할 때만 손보면 됩니다:
  - **`domainPrompt`**: LLM에 주는 서비스 용어 사전. 잘 채울수록 분류가 정확해집니다
  - **`categoryKeywords`**: 휴리스틱 모드가 카테고리를 고를 때 쓰는 추가 키워드
  - **`relevanceHints`**: 관련 글로 인정하려면 함께 나와야 하는 문맥 단어
  - **`excludeHints`**: 이 단어가 있으면 무관으로 판정 (동음이의어 차단, 아래 참고)

### 여러 서비스를 함께 추적하기

계열 서비스를 한 대시보드에서 보려면 `services` 배열을 씁니다. 있으면 최상위
`keywords`, `appstore`, `googlePlay`봅니다 **우선**합니다 (없으면 최상위 값이 서비스 하나가 됩니다. 구버전 호환).

```jsonc
{
  "displayName": "우리 서비스들",     // 대시보드 제목
  "services": [
    {
      "name": "서비스A",              // 목록에 배지로 표시된다
      "keywords": ["서비스A", "줄임말"],
      "appstore":   { "appId": "123456789" },
      "googlePlay": { "appId": "com.example.a" },
      "relevanceHints": ["A만의 용어"], // 전역 힌트에 더해진다
      "excludeHints": []
    },
    { "name": "서비스B", "keywords": ["서비스B"], "googlePlay": { "appId": "com.example.b" } }
  ]
}
```

- 수집, 분류, 집계가 **서비스별로 분리**되어 저장됩니다. 목록에 서비스 배지가 붙고,
  관련성 판정도 그 서비스의 키워드, 힌트로 이뤄집니다
- 앱이 없는 서비스는 `appId`를 비워 두면 그 소스만 건너뜁니다 (로그에 이유가 남습니다)
- **해외 서비스는 아직 이득이 적습니다**. 네이버, 커뮤니티 수집기가 한국어 소스 전용이라,
  해외 앱은 스토어 리뷰만 모입니다. 그 경우 `appstore.country` / `googlePlay.lang`을 맞춰야 합니다

> **왜 회사 고유명사만 설정에 두는가**: 이 저장소는 공개입니다. 코드와 프리셋에는 업종 수준의
> 일반 용어만 두고, **어느 회사, 어느 서비스인지 특정할 수 있는 값(서비스명, 키워드, 앱 ID)만**
> gitignore되는 `private/`에 둡니다. 그래서 새 머신에서도 채울 게 3개뿐입니다.

## 4. (권장) LLM 태깅 켜기: 추가 비용 0원

Claude Code CLI가 설치, 로그인돼 있으면 **개인 구독 요금으로** 태깅합니다.

```bash
npm install -g @anthropic-ai/claude-code
claude          # 최초 1회 실행해 로그인
claude --version
```

> **`claude --version`이 "명령을 찾을 수 없음"이면** npm 전역 bin 폴더가 PATH에 없는 것입니다.
> 이 경우에도 파이프라인은 표준 설치 위치(`%APPDATA%\npm\claude.cmd`, `~/.claude/local/claude` 등)를
> 자동으로 찾습니다. 그래도 안 되면 `.env`의 `CLAUDE_CLI_CMD=`에 전체 경로를 적습니다.
>
> VS Code에서 Claude Code 확장을 쓰던 머신이면 인증 정보(`~/.claude`)를 공유하므로 재로그인이 필요 없습니다.

API 키로 쓰려면 `.env`에 `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY`를 넣습니다.
대시보드의 **AI 분류 상태** 카드에서 `OpenAI API`를 고르면 기본적으로
`gpt-5.4-nano`를 사용합니다. OpenAI 호출은 Responses API, Structured Outputs,
`store: false`로 보내며 분류와 채널 브리핑이 같은 provider를 따릅니다.
어느 쪽도 쓸 수 없으면 키워드 휴리스틱으로 동작합니다. 무료지만 정확도가 낮습니다.

`gpt-5.4-nano`는 분류와 데이터 추출에 맞춘 기본 추천값이며 설정 화면에서 아래 5개 중
바꿀 수 있습니다. 단가는 표준 API의 텍스트 100만 토큰 기준이고, 설정 화면에도 같은 표를 표시합니다.

| 모델 | 용도 | 입력 | 캐시 입력 | 출력 |
|---|---|---:|---:|---:|
| `gpt-5.4-nano` | 분류, 추출 추천 | $0.20 | $0.02 | $1.25 |
| `gpt-5.4-mini` | 품질 우선 | $0.75 | $0.075 | $4.50 |
| `gpt-5-mini` | 균형형 | $0.25 | $0.025 | $2.00 |
| `gpt-4.1-mini` | 안정적 지시 이행 | $0.40 | $0.10 | $1.60 |
| `gpt-5-nano` | 최저 비용 | $0.05 | $0.005 | $0.40 |

### 모델 고르기 / 실제로 뭐가 돌았는지 확인

대시보드 **AI 분류 상태** 카드에서 고릅니다. 기본값은 `haiku`.

목록의 `(최신)`은 별칭이라 CLI가 호출할 때마다 그 시점의 최신 버전으로 바꿔 넘깁니다.
그래서 별칭만 봐서는 버전을 알 수 없어, 호출을 전부 `claude -p --output-format json` 으로 하고
응답의 `modelUsage` 키(정식 모델 ID)를 그대로 표시합니다.

| 어디 | 예시 |
|---|---|
| 카드 상단 | `지정 haiku, 실제 호출 claude-haiku-4-5-20251001` |
| 수집 로그 | `claude-cli 배치 1: 25/25건 분류 (claude-haiku-4-5-20251001)` |
| 수집 로그 끝 | 실행 합계: 모델 ID + 입출력 토큰 + 환산 비용 |

로그의 달러 값은 API 정가 환산치입니다. 구독 모드에서는 실제로 청구되지 않습니다.

버전을 묶으려면 별칭 대신 `claude-haiku-4-5` 같은 고정 항목을 고릅니다.
계정, 조직 설정에 따라 거부될 수 있는데(`Usage credits are required for this model.`),
저장하면 실제 호출을 한 번 해보므로 거부 사유가 카드에 바로 뜹니다.

`.env`의 `CLAUDE_CLI_MODEL`로도 지정할 수 있습니다. 다만 **카드에서 저장한 값이 우선**입니다
(카드 값은 DB의 `settings` 테이블에 저장 → `private/`를 옮기면 같이 따라갑니다).

## 5. 실행

```bash
npm run dev
```

- **대시보드** http://localhost:3000: 수집 현황 + 수집 주기 설정 + "지금 실행" 버튼
- **스케줄러**: 설정한 주기마다 자동으로 수집→태깅→요약→리포트. 첫 시작 시 1회 즉시 실행

주기는 UI에서 바꾸면 30초 이내 반영됩니다 (프로세스 재시작 불필요).

### 1회 수집량 조절

이 도구는 전수조사가 아니라 **검색 결과 상위 N개**를 가져옵니다. 그 N을 소스별로 정합니다.

| 소스 | 단위 | 기본 | 범위 |
|---|---|---|---|
| 앱스토어 | 페이지 (앱당, 1페이지=50건) | 3 | 1~10 |
| 구글플레이 | 건 (앱당) | 200 | 10~1000 |
| 네이버 블로그 | 건 (키워드당) | 50 | 10~100 |
| 네이버 카페 | 건 (키워드당) | 50 | 10~100 |
| 디시인사이드 | 건 (키워드당) | 50 | 10~200 |
| Threads | 건 (키워드당) | 30 | 10~100 |
| X | 건 (키워드당, 최근 7일) | 20 | 10~100 |
| X 월 예산 (`api` 경로 전용) | 달러 (이번 달 총액 상한) | 50 | 0~1000 |
| X 간격 (`web` 경로 전용) | 초 (키워드 사이 하한, 상한은 2.4배) | 8 | 3~120 |
| X 긴 휴식 (`web` 경로 전용) | % (간격 대신 크게 쉴 확률) | 15 | 0~50 |
| 더쿠 | 쪽 (게시판당, 1쪽=20건) | 5 | 1~20 |
| 다음 카페 | 건 (게시판당, 최신 20건이 상한) | 20 | 1~20 |

블로그와 카페는 엔드포인트가 다르고 응답도 다릅니다(블로그만 작성일을 줍니다). 그래서 따로 켜고 끕니다.
예전 설정에 `naver` 하나로 저장해 둔 값이 있으면 두 채널이 그 값을 물려받습니다.

대시보드의 **1회 수집량** 카드에서 바꾸면 다음 수집부터 반영됩니다. 카드에 이 설정으로
한 번에 최대 몇 건이 들어오는지, 그리고 소스별로 지금까지 실제 긁어온 범위(건수, 작성일)가
같이 표시됩니다. 값을 키우면 수집량과 **AI 호출량이 같이 는다**.

> **앱 리뷰(앱스토어, 구글플레이)는 값을 키워도 최근 글이 늘지 않습니다.** 그 앱에 달린 리뷰를
> 최신순으로 받는 구조라 이미 있는 걸 다 가져오는 중이면 **더 옛날 리뷰**가 딸려올 뿐입니다.
> 검색 소스(네이버, 디시, Threads, X)만 값을 키운 만큼 결과를 더 깊이 훑습니다.
> **X는 그 깊이가 곧 청구액입니다.** 다른 소스는 시간과 AI 호출만 는다.

### 소스 하나만 돌리기

기본은 6개 소스를 돕니다(X는 꺼진 채로 시작해서 7개 중 6개입니다). 줄이는 방법이 두 가지 있습니다.

- **끄기**: 수집량 카드에서 소스 체크를 풀면 이후 수집에서 계속 빠집니다
  (`sources.<키>` 설정으로 저장되며 `config.sources`봅니다 우선합니다)
- **한 번만**: 카드의 `[<소스명>만 실행]` 또는 `npm run collect -- --source=naver-blog`.
  **꺼 둔 소스도 이 방법으로는 실행됩니다**. 네이버 키를 방금 넣었거나 스크레이퍼를
  고친 뒤 그것만 확인할 때 씁니다. X도 이 경로로는 도니 과금에 주의해라

> **이 버튼은 소스만 한정합니다. 추적 서비스는 전부 돕니다.** 서비스 하나만 골라 수집하는 기능은
> 없습니다(조회 화면의 서비스 칩은 필터일 뿐 수집 범위와 무관합니다). 서비스 5개에 키워드가 9개
>흩어져 있으면 소스 하나를 돌려도 키워드 9개를 다 훑습니다.

> `--only`는 쓸 수 없습니다. npm 자체 옵션이라 npm이 삼켜서 스크립트까지 오지 않습니다.

### 날짜로 수집할 수는 없다

어느 소스도 "특정 날짜의 글"을 요청하는 파라미터가 없습니다. 전부 최신순으로만 줍니다.

| 소스 | 날짜 파라미터 | 정렬 |
|---|---|---|
| 앱스토어 RSS | 없음 | `sortby=mostrecent` |
| 구글플레이 | 없음 (`appId, lang, country, sort, num`이 전부) | `sort=NEWEST` |
| 네이버 검색 API | 없음 | `sort=date` |
| 디시 통합검색, Threads | 없음 | 검색 결과 순 |
| X 최근 검색 | 없음 (최근 7일 고정) | 최신순 |

그래서 날짜로 보려면 **수집은 다 해두고 조회할 때 거릅니다**. 대시보드의 기간 필터(`?period=7d`)가
그 역할입니다. 수집 단계에서 버리면 되돌릴 수 없지만, 저장해 두면 언제든 과거로 돌아갈 수 있습니다.

우선순위는 `대시보드에서 저장한 값 > 테넌트 설정의 collect > 기본값`입니다.
칸을 비우고 저장하면 테넌트 설정 값으로 돌아갑니다. 범위를 벗어난 값은 무시됩니다.

**자동 수집을 끄고 수동으로만 돌리려면** 스케줄러 카드의 `자동 수집` 체크를 풉니다
(`intervalHours = 0`으로 저장됩니다). 스케줄러는 계속 떠 있지만 주기 실행을 건너뛰고
[지금 실행] 버튼과 `npm run collect`만 받습니다.

목록은 **작성일(posted_at) 최신순**으로 정렬됩니다. 소스가 날짜를 안 주는 건(디시 검색 결과 일부)은
맨 뒤로 밀리고, 기간 필터를 걸면 빠집니다. 몇 건이 빠지는지는 기간 칩 옆에 표시됩니다.

## 6. 잘 되는지 확인

```bash
npm run collect        # 수집 파이프라인을 1회 즉시 실행
```

출력의 `태거:` 줄에 `claude-cli(...)`가 보이면 LLM 모드로 동작 중입니다.
`heuristic`이면 4번 단계를 다시 확인합니다.

> `npm run collect`를 다시 돌리면 **남은 것부터 이어서** 합니다.
> 한 번에 최대 2천 건까지 처리하므로 그보다 많으면 `collect`를 여러 번 돌립니다.

## 발표, 데모

- **`/tour`**: 실제 화면 위에 설명이 뜨는 제품 투어. 예시 데이터로 동작하므로
  수집 이력이 없는 노트북에서도 그대로 보여줄 수 있습니다. **시연에는 이게 가장 좋습니다**
- **`/?tour=1`**: 같은 설명을 실데이터 화면 위에 얹습니다. 발표에서 "이게 실제로 돈 결과"를 보일 때

실데이터 화면은 PostgreSQL을 쓰도록 설정할 수 있습니다. PostgreSQL 접속에 실패하면 `/`는
다른 곳에 쓰지 않고 **코드에 내장된 `/tour` 예시 데이터로 이동**합니다. 공모전 심사 중
DB 장애가 나도 제품 흐름은 볼 수 있고, 서로 다른 DB에 데이터가 갈라지지 않습니다.

## PostgreSQL 중앙 DB

집과 회사에서 같은 데이터를 보려면 각 PC의 `.env`에 같은 접속 정보를 넣습니다. **한 줄이 전부입니다.**

```ini
DATABASE_URL=postgresql://user_name:secret@example.db.host:5432/database_name?schema=feedback_radar&sslmode=require
```


| 쿼리 | 뜻 | 생략하면 |
|---|---|---|
| `schema` | 앱 전용 스키마 | `feedback_radar` |
| `sslmode` | `disable`, `auto`는 TLS 미사용 / `require`는 암호화 / `verify-full`은 인증서까지 검증 | `require` |
| `pool_max` | 프로세스당 최대 연결 수 | `1` |

libpq 표준 값도 받습니다(`prefer`, `allow`는 평문으로, `verify-ca`는 `verify-full`로 처리).
쿼리에 안 적으면 `PGSCHEMA`, `PGSSL_MODE`, `PGPOOL_MAX` 환경변수를 보충으로 읽습니다.

> **비밀번호의 특수문자는 percent-encoding합니다.** `#` → `%23`, `/` → `%2F`, `?` → `%3F`.
> `@`는 마지막 것을 구분자로 보기 때문에 그대로 둬도 됩니다. **`#`이 특히 위험합니다.** 인코딩하지
> 않으면 `.env` 파서가 그 앞에서 값을 잘라 버려서, 접속 실패가 아니라 **다른 비밀번호로 시도**합니다.

`npm run db:migrate:postgres`를 한 번 실행하면 스키마 아래에 필요한 테이블과 인덱스를
자동 생성하고 `private/data/feedback-radar.db`의 기존 데이터를 업서트합니다. 이후 웹과 수집
파이프라인은 PostgreSQL을 원본으로 씁니다. 같은 명령을 다시 실행해도 중복 행은 생기지 않습니다.

TLS를 지원하지 않는 구형 서버만 `sslmode=disable`을 씁니다. 이 경우 인증 정보와 데이터가
암호화되지 않으므로 단기 데모 외 용도로는 권장하지 않습니다. Vercel에서는 `DATABASE_URL`
하나를 비밀 값으로 등록합니다. 비밀번호가 URL 안에 들어 있으니 로그에 찍히지 않게 주의합니다.

> 항목별 변수(`PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`)로 적던 방식은 없앴습니다.
> 배포 환경에 같은 값을 아홉 번 등록하는 것이 번거롭고, 두 방식이 공존하면 어느 쪽이 실제로
> 쓰였는지 추적하기 어렵습니다. 옛 변수가 남아 있으면 기동할 때 안내가 뜹니다.

Vercel 배포판은 상주 스케줄러 대신 화면의 **[한 번 실행]** 요청 안에서 앱스토어,
구글플레이, 네이버 수집과 OpenAI 분류를 끝냅니다. Claude CLI와 시스템 Chromium이 없으므로
OpenAI를 강제하고 디시, Threads는 끕니다. 처음 수집량은 앱스토어 1페이지, 구글플레이 50건,
네이버 10건처럼 낮게 시작하며, 배포 화면에서 저장한 값은 `vercel.*` 설정으로 분리돼 로컬
수집량을 덮어쓰지 않습니다. 서비스/프롬프트 변경과 자동 수집 주기 설정은 계속 잠겨 있습니다.

```ini
OPENAI_API_KEY=secret
```

`TAGGER_MODE`는 넣지 않아도 됩니다. 배포 환경을 감지하면 코드가 OpenAI로 강제하고, 키가
없으면 그 자리에서 알려 줍니다. 모델도 기본값이 있고 화면에서 고른 값이 우선합니다.

테넌트 설정은 DB에 있으므로 배포에 따로 넣을 것이 없습니다. 로컬에서 처음 실행할 때 설정
파일이 DB로 한 번 옮겨지고, 그 뒤로는 배포본도 같은 값을 읽습니다. 서비스명을 바꾸면 재배포
없이 반영됩니다. `RADAR_CONFIG_JSON` 환경변수는 DB봅니다 우선하는 비상용 우회로만 남겨 뒀습니다.

슬라이드 페이지(`/pitch`, `/deck`)는 없앴습니다. 텍스트로 설명을 반복하는 대신 동작하는 화면을
보여주는 쪽이 낫고, 두 페이지의 내용은 둘러보기와 이 README에 이미 들어 있었습니다.
기술 설계는 각 소스 파일 주석에 적어 둡니다.

## 상시 실행 (24시간 켜 두는 PC)

```bash
npm run build && npm run start
```

대시보드는 **127.0.0.1(로컬 전용)** 로 바인딩됩니다. 대시보드에는 인증이 없으므로
같은 네트워크의 다른 기기에서 열려면 위험을 감수하고 `apps/web/package.json`의
`start` 스크립트에서 `-H 127.0.0.1`을 지웁니다.

**Windows**
- 절전 방지: `설정 → 시스템 → 전원 및 배터리 → 화면 및 절전`에서 절전을 "안 함"으로,
  또는 관리자 PowerShell에서 `powercfg /change standby-timeout-ac 0`
- 백그라운드 유지: [pm2](https://pm2.keymetrics.io/) 또는 `작업 스케줄러`에 "로그온 시 시작"으로 등록

**macOS**
- 잠자기 방지: 시스템 설정에서 잠자기 끄기, 또는 `caffeinate -s npm run start`
- 터미널 종료 후에도 유지: `mkdir -p logs && nohup npm run start > logs/app.log 2>&1 &` 또는 pm2

포트 3000이 이미 쓰이고 있으면 `.env`에 `PORT=3001`처럼 지정합니다.

# 집 PC ↔ 회사 PC 오가며 쓰기

코드는 GitHub로 옮기고, 수집 데이터는 PostgreSQL을 원본으로 공유합니다. 각 PC에는 테넌트 설정
(최초 1회만 필요합니다)과 API 키, DB 접속 정보가 든 루트 `.env`만 안전한
경로로 전달하면 됩니다.
수집 데이터는 압축본에 없습니다. 접속 정보만 있으면 새 머신이 같은 데이터를 봅니다.

## 옮길 때 (기존 머신)

```bash
npm run pack
```

`private-zip/feedback-radar-private_2026-08-02_0426.zip` 처럼 **만든 날짜, 시각이 붙은** 파일이
생깁니다. 이 파일 하나만 옮기면 됩니다. 덮어쓰지 않고 쌓이므로, USB에 옮긴 게 언제 것인지
이름만 보고 알 수 있습니다 (오래된 건 직접 지우면 됩니다. 스크립트가 목록을 같이 보여줍니다).

수집이 돌고 있어도 괜찮습니다. 담기는 것이 설정과 접속 정보뿐이라 수집과 겹칠 일이 없습니다.

| 스크립트가 알아서 하는 것 | 왜 |
|---|---|
| DB를 backup API로 다시 뜹니다 | WAL 모드라 파일을 그냥 복사하면 최근 데이터가 빠집니다 |
| `.db-wal`, `.db-shm` 제외 | 스냅샷에 이미 반영돼 있습니다. 넣으면 오히려 어긋납니다 |
| `private-zip/` 에 만듭니다 | `private/` 안에 두면 다음 압축에 그게 또 들어가 중첩됩니다 |
| `private-zip/` 은 gitignore | 폴더 이름 + `*.zip` 두 겹으로 막혀 있습니다 |

## 받을 때 (새 머신)

```bash
git clone https://github.com/bedcoding/feedback-radar
cd feedback-radar
npm install
```

압축을 **레포 루트에서** 풉니다 → `private/` 폴더와 `.env`가 생기면 성공.

**Windows (PowerShell)**
```powershell
Expand-Archive feedback-radar-private_2026-08-02_0426.zip -DestinationPath . -Force
```

**macOS / Linux**
```bash
unzip feedback-radar-private_2026-08-02_0426.zip
```

```bash
claude auth login    # 인증 정보는 압축본에 없다 (~/.claude). 머신마다 따로
npm run dev
```

### 새 머신 체크리스트

| # | 할 일 | 확인 |
|---|---|---|
| 1 | Node 20.12 이상 | `node -v` |
| 2 | `npm install` (레포 루트에서) | 네이티브 모듈이 없어 그대로 설치됩니다 |
| 3 | 압축 풀기 | 루트에 `private/feedback-radar.config.json`과 `.env`가 보이면 성공 |
| 4 | claude CLI 로그인 | `claude auth status`: **`private/`에 안 들어 있어 머신마다 따로 해야 합니다** |
| 5 | `npm run dev` → http://localhost:3000 | 카드가 "Claude 구독 (추가 비용 0)"이면 끝 |

> **`node_modules`는 옮기지 않습니다.** 용량만 크고 `npm install`로 그대로 재현됩니다.

> **Windows에서 `claude`를 못 찾으면** 카드의 입력칸에 `%APPDATA%\npm\claude.cmd`를
> 펼친 전체 경로로 적고 저장합니다.

## `private/` 없이 새로 세팅할 때 (예: 회사 PC에서 처음 여는 경우)

**서비스 이름만으로는 부족합니다**. 앱 ID는 이름에서 유추할 수 없기 때문입니다.
대신 아래 4줄이면 끝납니다.

```bash
npm install
npm run setup                       # private/ 생성 + 업종 프리셋과 루트 .env 복사
npm run find-app -- "서비스명"       # 앱스토어, 구글플레이 앱 ID 출력 → 복사
# private/feedback-radar.config.json에서 displayName, keywords, appId 2개 채우기
npm run dev
```

채워야 할 값은 이 4개뿐입니다. **업종 용어 사전은 프리셋에 들어 있어 다시 적을 필요가 없습니다.**

| 값 | 어디서 얻나 |
|---|---|
| `displayName` | 화면, 리포트에 표시할 이름 (아무 문자열) |
| `keywords` | 웹 검색어. 정식명 + 줄임말, 별칭을 함께 넣으면 수집량이 는다 |
| `appstore.appId` | `npm run find-app` 결과의 숫자 |
| `googlePlay.appId` | `npm run find-app` 결과의 패키지명 |

선택 사항: `.env`의 네이버 API 키(없으면 네이버만 건너뜀), X Bearer 토큰(유료, 없으면 X만 건너뜀),
그리고 LLM 태깅을 쓰려면 `claude` 로그인.

> 값을 안 채운 채 실행하면 파이프라인이 **안내 메시지와 함께 멈춥니다**. 자리표시자를
> 그대로 검색해서 헛돌지 않게 하기 위한 것입니다.
>
> 집에서 쓰던 설정을 그대로 쓰려면 위 과정 없이 `private/` 폴더와 루트 `.env`만 옮기면 됩니다
> (아무것도 안 채워도 됨). `npm run pack`이 둘을 한 압축본에 담습니다.

> **DB까지 옮길지 선택**: `private/data/`를 빼고 옮기면 새 머신에서 빈 DB로 시작합니다.
> 두 머신에서 각각 수집하면 데이터가 갈라지므로, **한쪽을 주 수집기로 정하고** 다른 쪽은
> 개발용으로 쓰는 편이 낫습니다. USB, 개인 클라우드로 `private/`를 통째로 동기화해도 되지만,
> **동시에 두 머신에서 실행하면 DB가 충돌**합니다.

## 데이터 없이 코드만 확인할 때

`private/`가 없어도 실행은 됩니다. example 설정으로 돌아가고, 대시보드는 비어 있으며,
화면은 서비스명 대신 자리표시자를 보여줍니다. `/tour`는 예시 데이터로 그대로 동작하므로
이 상태에서도 전체 기능을 볼 수 있습니다. 코드 리뷰나 새 머신 점검에 쓸 수 있습니다.

# 참고

## 태깅(요약) 모드

| 모드 | 조건 | 비용 |
|---|---|---|
| `cli` | 머신에 Claude Code 설치+로그인 | **구독 요금에 포함 (추가 비용 0)** |
| `openai` | `.env`에 `OPENAI_API_KEY` | OpenAI 정가 또는 계정의 데이터 공유 무료 한도 |
| `anthropic` | `.env`에 `ANTHROPIC_API_KEY` | Anthropic 종량제 |
| `heuristic` | 조건 없음 | 무료 (키워드 규칙 기반, 정확도 낮음) |

기본은 자동 선택(cli → 설정된 API → heuristic). `.env`의 `TAGGER_MODE`나 대시보드에서
강제할 수 있습니다. CLI와 OpenAI API 모드는 호출 수를 아끼기 위해 기본 25건씩 배치로 분류합니다.
구독 rate limit(5시간 윈도우)이 있으므로 **수집 주기는 하루 1~3회를 권장**합니다.

**관련성 필터**: 짧은 검색 키워드는 동음이의어 노이즈를 끌고 옵니다 (예: "애플" → 과일, IT 기업).
태거가 건별로 "실제 우리 서비스 얘기인가"를 판단해(`relevant`) 무관 글을 리포트, 집계에서 제외합니다.
무관 글은 **지우지 않고 표시만** 하므로 대시보드의 "걸러진 글" 탭에서 판정이 맞았는지 확인할 수 있습니다.

정확도를 올리는 순서 (효과 큰 것부터):

| 방법 | 효과 | 방법 |
|---|---|---|
| **LLM 태깅 켜기** | ★★★ | `claude` 로그인. 규칙 기반과 문맥 이해의 차이가 가장 큽니다 |
| **`excludeHints` 추가** | ★★★ | "걸러진 글" 탭에서 반복되는 노이즈 주제를 찾아 그 분야 단어를 넣습니다 |
| **`domainPrompt` 보강** | ★★ | 자체 재화, 이벤트 명칭, 은어를 적을수록 LLM 분류가 정확해집니다 |
| **키워드 좁히기** | ★★ | 너무 짧은 키워드는 노이즈를 부릅니다. 정식명 위주로 |
| **`relevanceHints` 추가** | ★ | 휴리스틱 모드에서만 쓰입니다 |

> **별도의 "학습"은 없습니다.** 모델을 파인튜닝하지 않고, 위 설정값이 곧 프롬프트로 들어가
> 분류 기준이 됩니다. 즉 **설정을 고치는 것이 이 도구에서의 학습**입니다.
> 잘못 분류된 건을 발견하면 그 패턴을 `excludeHints`나 `domainPrompt`에 반영한 뒤
> `npm run retag && npm run collect` 로 전체를 다시 분류하면 됩니다.

## 환경변수 (레포 루트 `.env`)

| 변수 | 설명 |
|---|---|
| `TAGGER_MODE` | 태깅 모드 강제: `cli` \| `openai` \| `anthropic` \| `heuristic` (기본: 자동) |
| `TAGGER_API_PROVIDER` | 구버전 `TAGGER_MODE=api`에서 `openai` 또는 `anthropic` 선택 |
| `CLAUDE_CLI_CMD` | claude CLI 경로 (기본: PATH → 표준 설치 위치 자동 탐색) |
| `ANTHROPIC_API_KEY` | Anthropic API용. 모델은 `TAGGER_MODEL`로 덮을 수 있습니다 (기본 `claude-haiku-4-5`) |
| `OPENAI_API_KEY` | OpenAI API용. 모델은 화면에서 고르며 `OPENAI_MODEL`로 덮을 수 있습니다 (기본 `gpt-5.4-nano`) |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | [developers.naver.com](https://developers.naver.com/apps) 무료 발급 |
| `X_BEARER_TOKEN` | X 경로를 `api`로 쓸 때만 필요. [developer.x.com](https://developer.x.com) App-only Bearer, **종량제 유료**. `web` 경로는 토큰이 필요 없습니다 |
| `DEFAULT_INTERVAL_HOURS` | 최초 기본 주기 (이후 UI에서 변경) |
| `PORT` | 대시보드 포트 (기본 3000) |
| `RADAR_CONFIG_JSON` | 테넌트 설정 JSON. DB와 파일보다 우선하는 비상용 우회 (평소에는 비워 둡니다) |
| `DATABASE_URL` | PostgreSQL 접속 정보 **한 줄** (커밋 금지). 이것만 있으면 중앙 DB를 씁니다 |
| `PGSCHEMA` / `PGSSL_MODE` / `PGPOOL_MAX` | URL 쿼리에 안 적었을 때만 쓰이는 보충값 |

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 리포트 날짜가 하루 어긋납니다 | 리포트의 '하루'는 **실행 머신의 로컬 날짜** 기준입니다. UTC로 동작하는 서버, 컨테이너에서 돌린다면 `TZ=Asia/Seoul`을 지정할 것 |
| `태거: heuristic`만 나옵니다 | claude CLI 미설치, 미로그인. 아래 줄의 방법으로 설치 여부부터 확인한 뒤 `CLAUDE_CLI_CMD` 지정 |
| Windows에서 `claude`가 **'인식되지 않습니다'** | **미설치가 아니라 PATH 문제일 때가 많습니다.** npm 전역 bin(`%APPDATA%\npm`)은 PowerShell PATH에 안 들어가는 경우가 있습니다. 전체 경로로 확인합니다: `& "$env:APPDATA\npm\claude.cmd" auth status`. 파일이 있으면 설치는 된 것이고, 이 도구는 그 표준 위치를 자동으로 찾으므로 **수집은 정상 동작합니다**(터미널에서 직접 칠 때만 경로가 필요합니다) |
| `태거: openai`인데 CLI를 쓸 줄 알았습니다 | `claude auth status`는 `loggedIn: true`인데 실제 호출이 403 `Your organization does not have access to Claude`로 거부되는 경우가 있습니다. 로그인 문제가 아니라 그 계정/조직에서 헤드리스 `claude -p` 호출이 막힌 것이라, 다시 로그인해도 같습니다. 코드는 이걸 감지해 API 키 → 휴리스틱 순으로 폴백합니다. **DB가 중앙 공유이므로 CLI가 되는 다른 머신에서 `npm run collect`를 돌리면 같은 데이터에 반영됩니다** |
| 네이버 결과가 0건 | `NAVER_CLIENT_ID`/`SECRET` 미설정. 없으면 조용히 건너뜁니다 |
| X 결과가 0건 | 소스가 꺼짐(기본값)이거나, `web`은 세션 없음, `api`는 토큰 없음. 수집량 카드의 배너와 콘솔에 사유가 찍힙니다 |
| X 배너에 "계정이 제한" | `web` 경로에서 계정이 막혔습니다. 설정 탭에서 [세션 지우기] 후 새 임시 계정의 쿠키를 넣어라 |
| X 배너에 "구조를 찾지 못했습니다" | X 페이지 구조가 바뀌었습니다. `x-web.ts`의 `article[data-testid="tweet"]` 선택자를 점검해라 |
| X만 갑자기 안 돌음 | 월 예산 한도에 닿았을 수 있습니다. 수집량 카드의 `X 월 예산` 줄에서 사용액을 확인해라. 예산 `0`은 '제한 없음'이 아니라 '쓰지 않음'입니다 |
| X가 401, 429 | 401은 토큰이 잘못됐거나 등급이 최근 검색을 포함하지 않는 경우, 429는 호출 한도. 둘 다 그 키워드만 건너뜁니다 |
| `브라우저 기동 실패` 경고 | Edge/Chrome 없음. `npx playwright install chromium` 실행. 다른 소스는 계속 수집됩니다 |
| 대시보드가 비어 있습니다 | 아직 수집 전. `npm run collect` 실행 |
| 대시보드 숫자와 DB가 안 맞습니다 | 웹과 스케줄러가 같은 `DATABASE_URL`을 보는지 확인 (스키마까지 같아야 합니다) |
| `/`가 `/tour?fallback=db`로 이동합니다 | PostgreSQL 접속 실패. DB 서버 상태와 `DATABASE_URL`을 확인 |
| `PGHOST는 더 이상 읽지 않습니다` 경고 | 항목별 변수로 적어 둔 옛 설정. `DATABASE_URL` 한 줄로 바꿉니다 |
| 포트 3000 충돌 | `.env`에 `PORT=3001` 지정 |
| PDF 내려받기가 404 | `npm run deck` 미실행. 대시보드를 띄운 상태에서 실행 |
| 화면에 `{서비스명}`이 보입니다 | DB에도 파일에도 설정이 없거나, `displayName`을 아직 안 채운 것 |
| `설정을 아직 채우지 않았습니다` 로 중단됨 | `keywords`에 `{ }` 자리표시자가 남아 있음. 본인 서비스 값으로 교체 |
| 앱스토어, 구글플레이만 0건 | `appId` 미설정. 실행 로그에 `appId 미설정, 건너뜀` 이 찍힙니다 |

## 새 서비스에 이식하기

테넌트 설정의 키워드, 앱 ID, `domainPrompt`(서비스 용어 사전)만 교체하면
동일한 파이프라인이 다른 서비스의 피드백 레이더가 됩니다. **코드 수정 불필요.**
