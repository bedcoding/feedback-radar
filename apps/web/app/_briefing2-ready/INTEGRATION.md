# 브리핑2 원본 연결 — 채택 시안 07

## 범위와 현재 상태

원본 앱의 공통 `DashboardView`에 `brief2` / 브리핑2 탭을 추가했다.
`apps/web/app/page.tsx`가 `loadBriefing2ReadyData`로 자료를 읽고,
`Briefing2Content`를 `briefing2Reader` 슬롯에 전달한다. 기존 브리핑·목록·카드·채널별
탭과 전역 CSS는 유지한다. 이 문서는 연결된 코드와 이동 계약을 설명하며,
원본에서의 브라우저 검증은 완료했으며 결과는 `VERIFICATION.md`에 기록했다.

- 실제 경로: `/?tab=brief2&sdate=2026-08-20`
- 서비스 선택: 위 주소에 `service=서비스명` 추가. 생략하면 전체 서비스를 본다.
- 탭 본문에는 시안 목록·비교 설명·중복 날짜 도구줄을 넣지 않는다.
- 이 폴더는 `_dashboard`, `_briefing2`, `briefing-lab`을 실행 시 가져오지 않는다.
- 읽기 전용 조회만 수행한다. 수집, 분류, AI 요약 재생성, 설정 저장은 없다.
- 자료가 다른 작업에서 바뀌면 조회 결과도 바뀐다. 이 화면의 시각은 실시간 수집 상태를 뜻하지 않는다.
- 분리 작업본의 `/briefing2-preview`는 검토용 경로이며 원본 탭의 진입점으로 사용하지 않는다.

## 현재 서버 연결

`page.tsx`는 브리핑2를 선택했을 때만 `loadBriefing2ReadyData`를 호출한다.
조회 결과의 자료·서비스 목록·선택 상태·안내를 그대로 본문에 전달한다.
아래 본문은 `DashboardView`의 `briefing2Reader` 슬롯에서 렌더한다.

```tsx
<Briefing2Content
  data={briefing2Result.data}
  serviceOptions={briefing2Result.serviceOptions}
  selectedService={briefing2Result.selectedService}
  notice={briefing2Result.notice}
  location={{ pathname: routeBase, tab: 'brief2' }}
  itemsHref={createBriefing2ChannelHref(services.map((s) => s.name), routeBase)}
/>
```

`loadData.ts`가 하나의 REPEATABLE READ / READ ONLY 트랜잭션에서 데이터를 읽는다.
`@feedback-radar/core`의 기존 환경 설정과 PostgreSQL 접속을 사용한다.
`Briefing2ReadyScreen`은 선택적 서버 래퍼로 남아 있지만 현재 원본 페이지는 직접 호출하지 않는다.
데이터 조회와 본문 렌더는 서버 영역에서 처리하며 클라이언트에 데이터베이스 의존성을 전달하지 않는다.

## 이동 계약

| 입력 | 의미 |
| --- | --- |
| `location.pathname` | 날짜·서비스 이동과 GET 달력 폼이 향할 내부 경로 |
| `location.tab` | 날짜·서비스 이동에서 유지하는 `brief2` |
| `itemsHref(scope)` | `createBriefing2ChannelHref`가 제공하는 채널별 이동 함수. 지원하지 않는 범위는 `undefined` |
| `scope` | `source`, `service`, `country`, 선택적 `sentiment` |

날짜·서비스 이동에는 `briefing2Href`를 쓰며 '전체'는 service 파라미터를 지운다.
날짜 폼도 GET으로 같은 경로/탭/서비스를 유지해 자바스크립트 없이 이동한다.

건수와 사용자 피드백의 '더 보기'는 `tab=channels&period=all`로 이동한다.
원본 채널별 화면은 `sdate`로 작성일 하루를 제한하지 않으므로 브리핑에서 선택한 날짜를
목록 필터로 전달하지 않는다. 카드 건수는 선택한 날짜 기준이고 도착한 목록은 전체 기간 기준이다.
건수 링크의 설명과 '채널별에서 더 보기 · 전체 기간' 문구로 이동 범위를 알린다.

- `source`, `service`, `country`를 새 URL에 명시한다. 피드백 링크는 `sentiment=negative`도 보존한다.
- 설정에 있는 서비스 이름만 연결한다. 빈 서비스와 설정에서 제거된 서비스는 건수를 일반 텍스트로 남긴다.
- 국가는 소문자 두 자리 코드를 사용한다. 비스토어 채널의 빈 국가는 `country=none`, 즉 SQL NULL 범위로 연결한다.
- 구글플레이·앱스토어의 빈 국가는 과거 통합 요약일 수 있으므로 링크를 만들지 않는다.
- 전체 채널을 뜻하는 `all`, 여러 네이버 소스를 함께 조회하는 `naver`, 지원하지 않는 형식의 값은 연결하지 않는다.
- 날짜·기간 범위·관련성·카테고리·언어·페이지 등 이전 목록 필터는 상속하지 않는다.
  새 URL에서 관련성은 원본 기본값인 관련 글, 페이지는 1쪽이 된다.
- 링크를 만들 수 없어도 저장된 건수·요약·카드 내부 피드백과 원문 링크는 유지한다.

채널별 조회가 성공했지만 필터 결과가 0건이면 실제 빈 결과를 표시한다.
선택한 채널도 0건으로 목록에 남겨 이름을 유지한다. 데이터베이스 오류와 아무 필터 없는
빈 데이터베이스의 기존 샘플 폴백은 유지한다.

## 시각 명세

색상은 컴포넌트 `.root`에 정의한 화이트 팔레트다. 전역 다크모드나 색 변수에 의존하지 않는다.
폰트는 07과 같은 Pretendard 우선 스택이며 없으면 시스템 한글 폰트로 대체된다.

| 토큰/영역 | 값/역할 |
| --- | --- |
| `--bg` / `--panel` | `#f4f6f8` / `#ffffff` |
| `--text` / `--muted` | `#182238` / `#657084` |
| `--border` / `--link` | `#dfe4ec` / `#315fbd` |
| `--bar-fill` | `#3f68d8`, 저장 자료 추이 |
| 서비스 제목 | 22px / 600, 아래 선 없음 |
| 플랫폼 제목 | 15px / 600 |

| 건수/미분류 | 12px / 400, 보조 색. 건수 오른쪽 여백 8px |
| 읽기 면 | 흰색, 내부 여백 24px, 최대 폭 1040px |

서비스 전체를 감싸는 중첩 박스, 뇌 이모지, AI 브리핑 대제목, 스크롤 설명 줄은 없다.
도구줄 아래 한 번만 선을 넣고 24px 띄운다. 플랫폼 카드 내부 제목/본문 선은 유지한다.

## 상태와 상호작용

| 조건/조작 | 동작 |
| --- | --- |
| 전체 보기 | 플랫폼 바깥 카드 높이 최대 290px |
| 서비스 선택 + 여러 플랫폼 | 같은 행의 높이를 맞추되 최대 320px |
| 서비스 선택 + 하나의 플랫폼 | 자연 높이, 내부 스크롤/높이 버튼 없음 |
| 다음 행의 짧은 카드 | 빈 높이를 강제로 채우지 않음 |
| 모두 펼치기 / 기본 높이 | 내용과 피드백 열림 상태를 유지하며 높이 제한만 변경 |
| 피드백 펼치기 | 네이티브 details/summary. 카드 내부에서만 해당 위치로 스크롤 |
| 서비스 제목 | 접기 없음. 이동은 왼쪽/위쪽 색인에서 수행 |
| 날짜·서비스 변경 | URL 유지, 새 선택에 맞는 기본 높이로 초기화 |
| 원문 링크 | 안전한 http(s)만 새 탭에서 열기. 잘못된 URL은 텍스트 표시 |
| 미분류 양수 | 카드·그래프 다음 흰 영역의 마지막 줄에 전역 건수 표시 |
| 미분류 0/미지정 | 안내와 빈 안내 여백 모두 없음 |

스크롤은 네이티브 동작을 유지한다. Chromium의 12px 스크롤 영역에 투명 여백을 둬
막대는 6px로 보인다. 화살표·배경 레일은 숨기고, hover/키보드 초점 때 선명해진다.
스크롤할 내용이 있는 카드만 키보드 초점과 서비스·플랫폼·국가 이름을 제공한다.
제목과 닫힌 피드백 행은 카드 내부 고정이며 바깥 테두리는 스크롤하지 않는다.
불필요한 페이지 이동/애니메이션은 추가하지 않는다.

## 반응형·접근성·예외

- 1050px 이하: 서비스 색인을 본문 위로 이동하고 줄바꿈한다.
- 620px 이하: 단일 열, 읽기 면 18px/14px, 서비스 제목 20px, 카드 간격 24px.
- 380px 이하: 색인 글자/간격만 조금 줄인다. 본문 14px는 유지한다.
- 초점 순서는 서비스 색인 → 날짜 도구 → 높이 버튼 → 카드의 스크롤/원문/피드백 순이다.
- 선택 링크의 aria-current, 날짜 그룹 이름, 달력 입력 이름, 버튼 aria-pressed를 유지한다.
- Enter/Space로 피드백 및 높이를 조작한다. 펼치기 후 버튼 초점과 피드백 상태를 보존한다.
- 고대비 환경은 시스템 스크롤 색을 사용하고, 인쇄는 높이/내부 고정을 해제한다.
- 긴 서비스명·본문은 줄바꿈한다. 카드 수를 맞추려고 저장 글을 잘라내지 않는다.
- 원래 데이터 변환은 유지한다: 원문 대체문 최대 160자, 피드백 대체문 120자, 표본 최대 8건.
- 유효한 빈 날짜/없는 서비스는 다른 자료로 교체하지 않는다. 달력과 색인으로 복귀 가능하다.
- 날짜가 없으면 최근 저장일을 고른다. 잘못된 날짜는 기본 날짜와 짧은 안내로 처리한다.
- 브리핑2 조회 실패는 접속정보/쿼리/에러 스택 없이 새로고침을 요청하는 일반 안내를 공통 화면 안에 표시한다.
- 원본 공통 화면의 로딩 처리를 따른다. 날짜 폼은 서버 HTML의 GET 폼이며,
  로딩 경계를 변경하면 무자바스크립트 동작도 다시 확인한다.
- 추이는 기존처럼 실행일 기준 최근 기간이고 선택 작성일 기준 재계산은 하지 않는다.
- 생성 시각은 최신 저장 요약의 createdAt, 미분류는 날짜·서비스와 무관한 전역 값이다.

## 원본 검증 상태

탭·서버 조회·본문 슬롯·채널별 이동의 코드 연결을 적용했다.
원본 브라우저에서 날짜·서비스 선택, 전체 기간 채널별 이동, 피드백과 카드 높이 조작,
반응형 배치 및 기존 탭 이동을 확인했다. 비브리핑 탭에서 들어올 때는 오늘을 강제하지 않고
로더가 최근 저장일을 고른다. 명시된 유효 날짜와 브리핑 사이의 선택일은 유지한다.
공통 탭은 작은 화면에서도 이름이 한 줄을 유지하도록 가로 스크롤을 사용한다.
상세 검사 범위와 배포 제외 사항은 `VERIFICATION.md`를 따른다.

## 테스트

`node --import tsx --test apps/web/app/_briefing2-ready/*.test.ts apps/web/app/_channels/liveData.test.ts`

정리 동작을 합성 자료로 검사한다. `channelNavigation.test.ts`는 전체 기간 URL과 범위 차단을,

고정값으로 넣지 않고 07과 역할별 텍스트/링크/메타데이터를 비교한다.
테스트 파일은 배포 화면의 실행 경로에서 import하지 않는다.
